# CIB observation policy

## Status

Implemented procedure. This policy owns canonical CIB observation fidelity and its complete schema-field classification; it introduces no semantic or compatibility claim. Gate selection and the CIB execution procedure are in the [engineering policy](kernel/ENGINEERING-POLICY.md#contracts-and-evidence).

## Canonical CIB observation fidelity

This table classifies every field of `canonical-result.schema.json#/$defs/state` at schema depth, whether required or optional: each `$ref` is followed and each `oneOf` arm is expanded, so one path covers every wait kind that carries it. `engine-observed` means the raw producer value comes from pinned CIB deployment/runtime/history state; `adapter-derived` means a deterministic projection transforms retained engine facts; `adapter-decided` means project/profile policy supplies the value without a corresponding CIB semantic fact; and `not-claimed` means the field belongs to the project wire contract but the CIB lane makes no fidelity claim for it. A parent and child may differ because a composite collection or identity can mix observed, derived, decided, and unclaimed components, and a path written by several wait kinds takes the weakest class among them.

The CIB runner fills the state in `CibSevenStateProjector` (status, logical time, root variables) and `CibSevenOpenWaitProjector` (open waits, with `CibSevenOccurrences` supplying occurrence identity), and each basis cell names the method that writes the field. A field the runner writes only at the kernel's default, a fixed empty list or null, is `not-claimed`: CIB exposes no fact for it. The runner projects the root scope's variables only, so `scopes` is `not-claimed` throughout. Rule-level fidelity remains in the [kernel semantics documents](kernel/semantics/) and the [relation register](CIB-BPMN-RELATION-REGISTER.md) rather than this canonical field table. The recursive portable value members (`businessValue`) are not expanded: the `value[].value` row of each value carrier classifies every nested List or Map member, and the guard stops descending at that definition.

Retained `stateQueries` bind canonical status, logical time, and the root scope's Process-variable projection to raw public runtime/history queries and the controlled engine clock; `CibSevenStateProjector.rootVariables` reads every root-scope variable from history rather than a name set derived from commands. The task, Message-subscription, timer, effect and incident job snapshots retain the raw rows from which `CibSevenOpenWaitProjector` projects `openWaits`. No TypeScript consumer reads these snapshots: the runner's projector owns the projection, and the hosted lane reproduces every retained result from them.

Some command outcomes are `adapter-decided` too: `CibSevenCommandExecutor.timerFire` answers `rejected` without a CIB call when no open Timer wait matches the named occurrence, when the firing's deadline is not the wait's, when its `at` is before the deadline, or when `at` would move the controlled clock backwards. In a population run, `CibSevenPopulationCommands.timerStart` answers `rejected` without a CIB call when the named deployment ordinal is not an accepted deployment, when `at` is before `dueMs`, or when the start Event of that deployment's root definition has not exactly one Timer job or that job is not due at `dueMs`. These are preconditions of the scenario protocol, not CIB observations.

Two command outcomes are `adapter-derived`, one rule for a CIB refusal that changes no state: CIB raises it before it changes anything, so the runner answers `rejected` where CIB's transaction records a rollback. In a single-instance run, `CibSevenCommandExecutor.deliver` answers `rejected` when CIB's criteria correlation throws `MismatchingMessageCorrelationException`, which CIB throws for no matching execution and for several while it selects the target, before it triggers anything (`CorrelateMessageCmd.java:86-88`, `DefaultCorrelationHandler.java:46-53`); every other CIB failure of a delivery stays `rolledBack`. In a population run, `CibSevenPopulationCommands.apply` answers `rejected` for the refusals CIB raises before it changes any state, told apart by their identifiers: CIB's condition handler refusing an `evaluateConditions` without a Conditional start in scope, as `ENGINE-13043` when no deployment holds one and `ENGINE-13042` when the named definition declares none (`DefaultConditionHandler.java:56`, `:96`), before `EvaluateStartConditionCmd` instantiates anything (`EvaluateStartConditionCmd.java:54`, `:61-63`); and the correlation builder refusing a start-only publication that carries a Process or local variable criterion, as `ENGINE-13026` (`CommandLogger.java:172-175`), before it executes a command (`MessageCorrelationBuilderImpl.java:249-257`, `:332-336`). Any other failure of an evaluation or a publication stays `rolledBack`. A population publication keeps its `rolledBack` outcome with a `noMatch` or `ambiguous` resolution (`CibSevenPopulationCommands.apply`), told apart by the identifier CIB's command logger gives the two several-candidate refusals, `ENGINE-13030` and `ENGINE-13031` (`CommandLogger.java:192-206`), never by their wording.

Neutral projection does not increase source-binding independence. The raw Camunda binding to neutral protocol/operation translation is performed once by the kernel reader; neither kernel derives that translation from source bytes.

## Population evidence

This table classifies every field of `cibseven-population-evidence.schema.json` at schema depth, as the canonical table does, and states how the [population comparator](../packages/differential/src/population-comparator.ts) treats it and why. A reference into another schema is classified where that schema is: each `processStates[]` item is a canonical state, classified above and compared at `atCibBoundary`, and the envelope's identities are bound by [the evidence script](../scripts/cibseven-population-evidence.ts).
