## Row status

The kernel column reads: `accepted`, the row is `done` and the listed kernel scenarios still witness its acceptance; `slice`, the Lean and TypeScript kernels execute the listed scenarios, which cover part of the row, and the rest of its acceptance is open; `refused`, every listed scenario is refused at admission with the code shown; `absent`, no kernel scenario exercises the row; `integration`, a task of the coverage target's [Integrated qualification](../PRACTICAL-CIB7-COVERAGE-TARGET.md#integrated-qualification) or [Final acceptance](../PRACTICAL-CIB7-COVERAGE-TARGET.md#final-acceptance) table is `done` on the hosted qualification runs its evidence cell links, not on a kernel scenario. The executable corpus guard holds this column to the target's State column and to `scenarios/open-rows/owners.json`: a `done` task is `accepted` with a linked scenario (or `integration` with a linked hosted run), and every row links each directory it owns. Scenarios are discovered from `scenarios/` and `packages/differential/test/fixtures/`; the [kernel behavior oracle](../../packages/differential/test/kernel-behavior-oracle.integration-test.ts) (guard 16) holds the Lean and TypeScript kernels to the same result on every one, and the kernel to the retained CIB Seven result on every scenario that carries a `*cibseven-evidence.json` sibling: at [Verify 43529476152](https://github.com/mbackschat/bpmn-lean-experiment/actions/runs/43529476152) (2026-11-14) the integration pipeline ran 1,790 scenarios and 94 populations against 1,616 retained CIB results, with 0 kernel disagreements and 361 evidence disagreements, all classified. A journey row's retained business model is the BPMN source of its linked scenario directory. Lean and TypeScript agreement is a transcription check, never evidence of meaning.

[PC-DATA-02](../PRACTICAL-CIB7-COVERAGE-TARGET.md#business-data-and-expressions) is accepted: the kernel admits and refuses scenario values by whole-scenario support, direct refusal and strict wire decoding at the Human completion and Service result ([admission semantics](semantics/ADMISSION-SEMANTICS-SPEC.md#open-rows)).
