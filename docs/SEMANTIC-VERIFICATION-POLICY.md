Activity occurrence adoption is `shared` only where the guarded project-owned occurrence and issuing discipline serve multiple completed slices, `slice-local` where one bounded slice consumes it while other family shapes remain separate, `open` where the family needs but lacks that account, and `not-applicable` where the current family obligation owns no Activity body or attached-handler identity.

Multiple-enabled closure classifies the family’s own closed internal-operation frontier rather than downstream dependency operations: `not-reachable`, consistently `rejected`, `order-invariant`, semantic-input `explicit-choice`, `mixed`, or `open`. Composition is `reusable` for the same named mechanism and result domain across completed users, `profile-local` for one bounded profile, `mixed` for a reusable kernel beside profile-local or separate obligations, and `open` where no operational composition evidence closes the dimension. ## Executable corpus and experiment gates

During research/manifest edits against an already built source package, use the reuse-only corpus test. It checks exact retained/external bytes, Git revisions, official archive/entry digests, licences, clone families, mechanism vocabulary, compiler admission, pipeline registration, generated rankings and catalog eligibility. On clean checkout or before committing execution/readiness claims, run `./scripts/doctor.sh research` then `./scripts/pnpm.sh run test:model-corpus`: build the existing differential dependency graph once, then run static checks and retained models through the existing production target owners without another runner or rebuild. Catalog eligibility remains separate Product 2 evidence requiring a model-specific production Chromium journey; a retained model alone is insufficient.

Default verification runs the checked-source executable once through Lake, rebuilding when stale and kernel-checking Stage 3a declarations before evaluating `stageTwoAdmissionChecks`, `stageThreeAFrontierChecks` and positional-lowering negatives. Every widened checked-source closed union must keep frozen-experiment readers exhaustive and reject new variants outside its selected surface. [The entrypoint guard](../scripts/verification-entrypoint.test.ts) binds imports, command and negative-witness reachability; a passing build alone cannot replace those checks.

## Evidence lanes

An **evidence lane** identifies its producer, what passage establishes and what it cannot establish. Two lanes are distinct only for failure modes they detect independently: each capsule records the claim, separating defect and shared dependencies. Shared accounts, representations, fixtures or projections permit common-mode errors, while separate implementations may still disagree on transcription. Producers necessarily reproducing the assessed defect count once; agreement proves neither independence nor shared-input correctness.

This policy owns the term. A **work-stream** produces a lane's artifact; a **pinned baseline** is the checkout/configuration owned by [REFERENCE-INSTRUMENTATION-POLICY.md](REFERENCE-INSTRUMENTATION-POLICY.md); **rules** are individual propositions owned by [capsules](capsules/README.md).

| Lane | Passage can establish | Passage cannot establish |
|---|---|---|
| Normative BPMN/profile review | Explicit selected requirement/interpretation | Implementation behavior |
| CIB compatibility | Observed pinned behavior under the declared profile | Universal BPMN correctness |
| Lean | Executable explicit account and stated laws | Correctness of CIB, parser, TypeScript, Temporal or effects |
| Checked-graph lowering comparison | [Lean validation](../BpmnSemantics/SemanticProcessJson/DefinitionInput.lean) independently recomputes lowering and rejects unequal supplied Programs, detecting TypeScript lowering disagreement on maintained inputs | XML import, shared graph/account, profile translation or universal compiler/execution correspondence |
| TypeScript differential | Separately written core agreement on maintained inputs | Universal Lean correspondence or independently selected operational meaning |
| Temporal refinement | Tested core-visible durable results and replay | Unsupported BPMN meaning |
| MIWG interchange | Pinned-model structural import/reference/encoding behavior | Execution conformance |
| Seeded mutation | Comparator mutations of canonical-result clones detect the claimed field distinction; verifier mutations of retained raw observations detect raw-to-canonical projection drift | Projection completeness; comparator mutation says nothing about evidence projection |

No vote resolves source disagreement: classify it against standard, profile, CIB configuration, observation boundary and evidence before changing semantics. Lowering comparison is executable structural Program equality, neither a universal compiler theorem nor JSON spelling. [Boundary mutations](../packages/differential/test/semantic-differential-targets.ts) change origin/erase provenance to demand pre-execution rejection; downstream agreement misses a wrong Program shared by both targets.

[CIB observation policy](CIB-OBSERVATION-POLICY.md#canonical-cib-observation-fidelity) classifies every recursive `scenario.schema.json#/$defs/stateObservation` field as `engine-observed`, `adapter-derived`, `adapter-decided` or `not-claimed`, including activation, multiplicity, lifecycle state and timer deadline. Follow the schema, not a prose count; add raw observations only for engine-exposed facts. Reusing producer projection rules is a consistency check, never another independent lane.
