# Shared wire contracts

This directory owns language-neutral JSON Schemas for artifacts and canonical values that cross Java, Lean, TypeScript, and harness boundaries. Schemas define transport shape; semantic profiles and capsules define meaning.

## Evolution policy

The project is pre-release and keeps exactly one current representation of each wire contract. A breaking contract change replaces its producers, consumers, fixtures, schemas, and tests atomically. Parallel legacy readers, embedded format counters, compatibility switches, migration functions, and retained Temporal history baselines are deliberately absent until a first durable release boundary is approved.

Each document has a stable structural discriminator such as `semanticProfile`, `scenario`, or `cibSevenScenarioEvidence`. JSON Schema `$id` identifies the current schema itself. A semantic profile’s `id` identifies its reviewed behavioral meaning and declared normative or executable-oracle authority; changing that meaning or authority requires a new profile identity even when the JSON shape is unchanged.

This separation avoids routing every consumer through document-version switches while preserving the identity that actually matters to semantic claims. When production persistence or an immutable Temporal history baseline exists, compatibility must be designed from concrete retained artifacts and explicit migration/replay tests rather than speculative early formats.

Neutral scenarios contain no expected answer. CIB evidence is a separate immutable verifier input bound to the exact scenario and profile bytes. Target runners never receive it, and ordinary verification never regenerates it.

Schema validation is a boundary guard, not correspondence evidence. The maintained Ajv Draft 2020-12 gate validates artifacts, checks content identities and known CIB–BPMN relationships, and includes answer-smuggling, stale-evidence, and invalid-projection mutations. CIB calibration, Lean laws, TypeScript behavior, Temporal refinement, and differential comparison remain separate claim lanes.

Direct Activity associations carry directional endpoints: `source` is a closed Property or Process DataInput reference, and `target` is a closed Property or Process DataOutput reference. Service input mappings recognize the closed `{ kind: "enclosingVariable", name: string }` arm in both checked and Program contracts. The private [serial business-task account](../docs/capsules/SERIAL-BUSINESS-TASK-COMPOSITION-PROPOSAL.md#public-contract) owns its enclosing-context snapshot semantics, exact String/null result-source bindings and named-handler exclusions. The private [interrupting Message Event Sub-Process account](../docs/capsules/INTERRUPTING-MESSAGE-EVENT-SUBPROCESS-PROPOSAL.md#representation-and-lifetime) adds optional `interruptingMessageEventSubProcesses` declarations to both checked and Program contracts. Strict operation encoders, decoders, schemas and publication readers recognize that arm; recognition does not admit a public profile or hosted capability.

Runtime `eventSubProcessMessageSubscriptions` stores passive parent-owned listeners separately from ordinary Message waits. TypeScript omits it before Start and under older profiles, then retains an empty or singleton collection after successful Start, including terminal states; Lean uses an explicit list with an empty default. The listener uses the existing exact payload-free `deliverMessage` interaction and E1 subscription vocabulary. Dormancy creates no executing child or E2 occurrence; delivery, cancellation and handler retirement publish only their actual semantic lifecycles. The [IL contract](../docs/SEMANTIC-PROCESS-IL-SPEC.md#interrupting-message-event-sub-process) owns the transition boundary; no new stimulus, correlation rule, payload or platform workflow follows from these wire additions.

## Exact scalar and JSON boundary

Every wire integer represented as a JavaScript `number` is an integer in the inclusive range `0..9007199254740991`, with stricter bounds where the field requires them. Its raw JSON token must match `0|[1-9][0-9]*`; negative zero, fractions and exponent spellings reject even when conversion would produce an in-range integer. Validate the original token and safe range before lossy conversion, then enforce the typed field bounds. The [approved portable-value admission decision](../docs/capsules/PORTABLE-BUSINESS-VALUES-PROPOSAL.md#canonical-bytes-and-identity) owns this lexical selection. A closed wire document has no other numeric spelling: every numeral in it, at any position, is a wire integer token, so a noncanonical numeral is a transport refusal (HTTP `400`) even where the typed decoder would reject any number. Structured Work completion `fields` are closed wire values under [`SHW-DATA-01`](../docs/BPM-PLATFORM-STRUCTURED-HUMAN-WORK-SPEC.md). Generic JSON read without wire admission retains its separate contract and is not implicitly a wire integer.

Canonical identifiers are exact, non-normalized strings of Unicode scalar values. Their order is lexicographic by scalar value, not JavaScript UTF-16 code units, Java `String.compareTo`, locale, UTF-8 bytes, or normalized text. Canonically ordered arrays use this comparison. Canonically equivalent Unicode spellings remain distinct unless a future contract explicitly changes the identity domain.

Wire readers decode UTF-8 fatally, reject duplicate object keys after escape decoding and reject unpaired surrogate encodings. Decoded member names remain own properties, including `__proto__`, so an unknown member cannot disappear into a host object's prototype. Unknown or missing fields, values outside closed enums, `null` where absence is required, absence where an explicit nullable field is required, invalid numeric tokens, and non-canonical array order are all boundary errors. This strictness applies before typed semantic decoding; ordinary parser behavior that overwrites a duplicate key or replaces invalid bytes or a surrogate is not authoritative.

## Portable semantic assertions

A target scenario contains only admitted model/profile identity and explicit semantic inputs. The shared value union recognizes exact tagged String, null, Boolean, safe non-negative integer, and ordered bounded String-list arms, while profile-aware execution decides which surface may use each arm. `startProcess.initialVariables` remains String/null for ordinary registered profiles and is exactly empty for the parallel User Task metadata composition. The registered Boolean completion, sequential metadata, parallel metadata, and structured Human Work profiles admit Boolean on User Task completion; only structured Human Work admits integer and String-list values there. Target runners produce canonical results without receiving expected outcomes, rule verdicts, oracle traces, or comparison tolerances.

The Message payload catch profile admits Boolean, safe non-negative Integer, String, and Null on `deliverPayloadMessage`; StringList remains outside that scalar profile. The payload-free `deliverMessage` arm remains structurally distinct, so absence is not encoded as null.

The bounded Message key-correlation checkpoint adds distinct `correlatedPayloadMessageCatchEvent` and `awaitCorrelatedPayloadMessage` definition arms, one private `deliverCorrelatedPayloadMessage` target stimulus, and one global `publishCorrelatedPayloadMessage` enabled interaction. Its String-only correlation payload is a non-empty tagged String, and both runtime arms carry the complete address: the exact Semantic Process program identity, Process id, operation-addressed Message channel, and CorrelationKey id. The target stimulus additionally requires a positive safe ingress ordinal plus the exact subscription, CorrelationProperty, and Process Property identities. No optional correlation field widens `intermediateCatchMessageEvent`, `payloadMessageCatchEvent`, `awaitMessage`, `awaitPayloadMessage`, `deliverMessage`, or `deliverPayloadMessage`; their existing wire shapes remain unchanged.

The Compensation trigger checkpoint adds one optional `compensationExecution` declaration and its exact root-owned `triggerCompensation` operation. Strict Program admission binds zero or more canonical subjects to the existing retention/snapshot declarations, the closed single-effect descriptor and input arms, canonical acyclic dependencies, and positive bounded limits. The hidden RuntimeState slice adds optional trigger and handler-effect-wait collections, preserves frozen parent context on deferred and active Event Sub-Process handlers, and adds a typed failed Process control/observation/receipt arm. The independent TypeScript and Lean evaluators implement the bounded private transition account: atomic eligible-source consumption, frozen-context restoration, complete maximal reverse-dependency frontiers, success continuation, fail-fast cancellation and failure, stale-result and capacity refusal, and retained nonempty succeeded tombstones; a zero-subject throw creates no trigger. The [registered Compensation account](../docs/capsules/COMPENSATION-TRIGGER-HANDLER-PROPOSAL.md#public-registration-implementation) owns exact source/profile admission and hosting evidence.

Portable assertions are verifier-side claims over canonical results or relations between results. A future assertion artifact must bind the exact scenario content digest, semantic profile, applicable canonical observation contract, and stable rule identifiers. A general assertion language remains deferred until repeated semantic capsules demonstrate the smallest useful contract.

## Schemas

- [semantic-profile.schema.json](schemas/semantic-profile.schema.json) validates current draft profiles with exactly one normative or executable-oracle authority.
- [bpmn-source-overlay.schema.json](schemas/bpmn-source-overlay.schema.json) validates the closed data-only source overlay shape; byte limits, strict JSON decoding, canonical order, uniqueness, profile equality, and descriptor membership are enforced by the source boundary.
- [scenario.schema.json](schemas/scenario.schema.json) validates every registered answer-free target scenario. The registered scenarios and their capsule families are owned by the artifact registry and differential catalog, and this document deliberately does not restate that inventory: a copied list drifts silently, and the guarded catalogs already reject an unregistered scenario. Its `variableValue` union includes the recursive portable Decimal, List and Map arms; the schema is only a necessary filter, because Map key order, the signed 64-bit coefficient range, container depth, node count and canonical bytes are enforced by the TypeScript validator, and no registered profile admits these arms.
- [engine-population-scenario.schema.json](schemas/engine-population-scenario.schema.json) validates the separate Message-correlation population input without widening the ordinary scenario or pipeline-case shapes. It reuses the existing BPMN resource, start, direct payload-delivery, correlated address, and provenance definitions, fixes two instances and one publication, and requires Lean/core/Temporal with explicit `cib: null`.
- [canonical-result.schema.json](schemas/canonical-result.schema.json) validates the current canonical outcome and trace.
- [cibseven-evidence.schema.json](schemas/cibseven-evidence.schema.json) validates the content-bound retained CIB evidence envelope.
- [checked-process.schema.json](schemas/checked-process.schema.json) validates the admitted source-facing graph contract.
- [semantic-process.schema.json](schemas/semantic-process.schema.json) validates the immutable Semantic Process definition contract.
- [semantic-publication.schema.json](schemas/semantic-publication.schema.json) validates the strict structural page, Query-result, and canonical full-export publication wire; the Product 1 decoder additionally binds its identities and operations to the exact admitted Semantic Process program and enforces every range and position equation.
- [flow-node-occurrence-publication.schema.json](schemas/flow-node-occurrence-publication.schema.json) validates the additive strict request, page, occurrence lifecycle, commit-time, and five-arm Query-result wire; the Product 1 decoder additionally enforces E1 batch alignment, canonical identities, lifecycle folding, and exact Program-owned element and scope facts.

The checked BPMN graph and Semantic Process schemas freeze the artifact boundaries from [the Semantic Process IL spec](../docs/SEMANTIC-PROCESS-IL-SPEC.md). The bounded source compiler produces both artifacts after structural graph and exact profile-capability admission has resolved operation-addressed Message definition chains or one direct Receive Task Message, definition-scope ownership, exact direct-parent Error handlers, identity-only Exclusive Merge endpoints, structured Inclusive split/task/join correspondence, exact Event-Based Gateway configuration-flow/catch correspondence, one namespace-qualified in-document called Process, raw Service Task bindings, the exact configured Task extension binding, the reviewed sequential Multi-Instance source role graph, or the bounded Compensation throw/handler/dependency graph. Every execution-admitted path consumes only the Semantic Process program with no per-family source exception. The schemas validate transport shape; they do not establish raw source translation, lowering correspondence, or operational semantics.
