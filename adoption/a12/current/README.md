# Current A12 adoption evidence

This optional generation applies the data-only source-overlay contract to the two preserved project-authored A12-shaped fixtures. Each scenario selects a product-neutral engine profile (the CIB Seven 2.0.0 mapped-success and mapped-boundary-Error Service Task profiles) and content-binds the exact overlay identity. The fixtures remain outside all product registries, builds, examples, and runtime packages.

The exact external A12 Workflows checkout remains read-only and is research input only. These project-authored fixtures are not copies of that EUPL-1.2 source and do not constitute an A12 add-on, handler implementation, migration, or distribution.

The scenarios keep the scenario shape that preceded the kernel's contract re-cut (they still carry an `observations` member), so no current target runner reads them; the [A12 boundary guard](../../../scripts/a12-boundary.test.ts) uses them only to check that the retained CreateDocument fixture stays project-authored and distinct from the external bytes.

## Boundary for a future A12 add-on

A deployable A12 add-on is not implemented here. Production adoption starts in a separate A12-owned repository after the BPM platform publishes its supported compile, start, observe, and command contract; the [A12 add-on boundary specification](../../../docs/A12-ADD-ON-BOUNDARY-SPEC.md) owns that boundary.

- A missing reusable BPMN mechanism or reviewed CIB relationship found while classifying an A12 model against the [A12 compatibility ledger](../../../docs/research/A12-WORKFLOWS-COMPATIBILITY-LEDGER.md) returns to the MIT engine as a neutral requirement. An A12 binding, handler, façade, blueprint, or migration concern stays in the A12-owned product.
- An A12-owned source overlay conforms to the engine's closed [overlay schema](../../../contracts/schemas/bpmn-source-overlay.schema.json) and binds its exact ID, SHA-256 and bytes to a selected neutral profile. These two overlays are examples, not production registrations or code to copy into core.
- A12 effect handlers run behind the engine's neutral effect contract and return only the typed effect results the kernel accepts. `DelegateExecution`, A12 service objects and product state never reach the Workflow or the kernel.

Keep the [legacy generation](../legacy/README.md) read-only. If continuing work appears to require editing it, importing the external A12 checkout, registering an A12 profile in the engine, or adding an A12-specific reader or Workflow branch, stop and reclassify the work because it has crossed the product or licence boundary.
