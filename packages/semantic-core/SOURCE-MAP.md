## Test ownership

Tests under [`test/`](test/) mirror these owners by contract or semantic family. The registry-driven [runtime-state preservation lane](../differential/test/runtime-state-preservation.test.ts) sits at the differential composition boundary so compiling every registered program does not add parser or catalog dependencies to this package. The [testing specification](../../docs/TESTING-SPEC.md) selects the applicable focused and repository gates.

The [Call pairing tests](test/call-activity-pairing.test.ts) distinguish a bijection from equal invoke/return counts using duplicated and distinct invoke identities that share one return while leaving another unclaimed.

The [canonical token storage tests](test/canonical-token-storage.test.ts) check raw complete-key order, multiplicity, and admitted execution prefixes. Position-valid reversed controls isolate the aggregate order check; separate projection controls retain duplicate-bucket and nonpositive-multiplicity refusal.

The [canonical scope storage tests](test/canonical-scope-storage.test.ts) check complete occurrence-key order and Scope, Call, and event-race counter order. Projectable reversed scope controls isolate aggregate refusal; ordinary child entry/removal and event-race arming/winner paths retain exact occurrence identity and high-water counters.

The [scope-creation preparation tests](test/internal-transition-scope-creation-preparation.test.ts) compare retained child-entry and Call-invocation patches and publications with actual admitted execution prefixes. The [embedded Sub-Process fixture](test/embedded-subprocess-fixture.ts) is shared with the existing [completion tests](test/embedded-subprocess-completion.test.ts). Constructed sibling populations check complete preparation frames, exact opposite-order states, and canonical publication without claiming source admission. Refusal cases cover forged preparations, ambiguous identities, provenance, owner census, unsafe issuance, and snapshot declarations.

The [scope-creation batch tests](test/internal-transition-scope-creation-batch.test.ts) cover child entry and Call invocation beside local control and every prepared arming kind, plus all four scope pairings. All permutations check complete predecessor preparations, actual publications, runtime and projection validity, optional collection presence, and retained counters. Stale and forged artifacts, census conflicts, snapshots, duplicate alternatives, and unsupported frontier members reject. Actual Start closure and insufficient-fuel rollback use constructed Programs explicitly outside profile admission; separate singleton controls retain admitted profiles.

The [regional preparation tests](test/internal-transition-regional-preparation.test.ts) compare Return, child/root Complete, Error, and Terminate with actual runtime steps and accepted publications. They retain bounded completion's parent-owned Activity/deadline withdrawal, unchanged high-water counters, optional omission, and refusal of forged selections, ambiguous operation identities, unprojectable collections, and snapshot declarations. Bounded withdrawal additionally rejects duplicate child declarations, wrong declaring operations or parent activations, duplicate Activity bodies or handlers, a Message with Timer coordinates, stale Timer activations, and duplicate Timer identities with changed payload or owner. Timer identity uniqueness precedes owner filtering. These preparation helpers do not admit regional production batches.

The [regional pair tests](test/internal-transition-regional-pair.test.ts) use the [shared regional fixture](test/internal-regional-pair-fixture.ts) to compare all Return/Complete/Error/Terminate pairings, bounded completion, and all seven independent arming kinds from the [shared arming fixture](test/internal-arming-operation-fixture.ts). Every execution prefix checks runtime and projection validity, exact opposite-order state, complete preparation, and actual accepted publication; regional removal preserves activation counters. Removing regional dependencies exposes false independence against a sibling task. These constructed Programs remain outside profile admission.

The [regional/local-control tests](test/internal-transition-regional-local-control.test.ts) pair every regional family with Duplicate, Synchronize, Choose, SelectMany, and SynchronizeSelected, including bounded completion. Both orders preserve complete preparation and exact final state, with validity and projection checks at every prefix. Contained Error/Terminate forks expose false independence when region and token-census dependencies are omitted; stale or forged preparation refuses in both orders. The [reverse Lean frame](../../BpmnSemantics/SemanticProcess/InternalLocalControlRegionalPreparationFrame.lean) derives complete local-control preparation after actual regional execution. Every constructed Program explicitly fails profile admission.

The regional preparation tests also use two bounded scopes to distinguish ownership validity from exact Timer declaration. Changing both an Activity's operation key and its Timer output, or swapping live child bodies, must fail open-occurrence projection even when the separate ownership and position checks pass. The projector validates Timer element, output, operation scope, shared owner, and the declared host before producing a binding; aliased output declarations fail graph admission.

The [regional Timer projection tests](test/internal-regional-timer-projection.test.ts) cover bounded scopes and interrupting/non-interrupting User Tasks. Removing an Activity or its Timer attachment leaves the separate runtime-defect list empty but refuses projection; advancing only the Timer identity, attachment, and counter preserves the exact open set. The [Lean scope/Error witnesses](../../BpmnSemantics/InternalRegionalCancellationProjectionConformance.lean) and [Task witnesses](../../BpmnSemantics/BoundaryTimerProjectionConformance.lean) cover the same former ordinal-join defect. `BTP-LEGACY-HOST-01` in the [regional owner](../../docs/INTERNAL-COMMUTATION-PROPOSAL.md#regional-preparation-prerequisite) owns the correction's review boundary. These constructed states establish no profile reachability.

The [containing-region removal tests](test/internal-transition-regional-removal.test.ts) check Terminate across two called Process roots, a Call plus bounded child/deadline, and a Call plus live child work. Predecessor-derived publication equals actual cancellation, every activation counter survives, and omitting descendants loses required scope exits. These compositions do not admit a source profile.

The [regional controller tests](test/internal-transition-regional-controller.test.ts) construct two scope activations containing the same SMI operation and arm both controller/Activity/task/Timer groups through the actual task operation. Error and Terminate each withdraw one complete group while preserving the other and every issuance counter. Every prefix passes runtime validity, complete controller binding, and public projection. Dropped controllers or Timers and extra orphaned Activities fail the binding oracle. Raw scope entry excludes this two-live-occurrence topology, so the constructed second scope establishes no source or entry reachability.

The [Call controller tests](test/internal-transition-regional-call-controller.test.ts) use the [shared SMI operation fixture](test/internal-sequential-operation-fixture.ts) to arm separate caller and called-instance SMI or PMI lifetimes. Actual caller-selected cleanup withdraws both called groups and preserves the complete caller group and all eight issuance collections, including a PMI completed middle slot and two pending children. Five PMI cleanup mutations fail; wrong caller identities remove nothing. Live called work still prevents normal Return preparation. These constructed Programs do not establish profile reachability.

The [parallel controller tests](test/internal-transition-regional-parallel-controller.test.ts) reuse the [two-activation fixture](test/internal-regional-controller-fixture.ts). Actual middle-child completion leaves two pending children and a completed slot in one activation; Error/Terminate removes the other activation's three pending children while preserving that complete binding, Process data, and all eight issuance collections. Missing children, controllers, Timers, and completed slots fail eight injected mutations. The fixture uses the runtime invariant's wider occurrence domain without broadening source admission.

The [regional ownership tests](test/internal-transition-regional-ownership.test.ts) separate predecessor validity from cleanup preservation: Return and ordinary completion refuse retained Activities whose bodies would disappear; Error and Terminate refuse removal of either member of a retained Message/Timer race. Separate predicate-only states isolate each tagged handler and complete occurrence identity without claiming whole-state validity. A valid two-record Return removes its owned Activity and preserves the outside Activity; Error/Terminate also permit removing a race together with both waits. The raw operations remain the independent failure oracle; the [regional preparation tests](test/internal-transition-regional-preparation.test.ts) also compare all six reference-retention masks with actual removal fields, including root retention and bounded withdrawal.

The [retention-frame tests](test/internal-transition-regional-retention-frame.test.ts) distinguish preserved ownership closure from complete preparation equality. Error/Terminate in disjoint regions can both remove one Activity through its owner or child-body edge; Timer/Message claims then disappear. Exact Activity writes reject that false independence, omitting them reproduces it, and forged preparation refuses execution. The constructed runtime-valid states establish no profile reachability.

The [private Timer alias tests](test/internal-regional-private-timer-alias.test.ts) preserve a public Task or Message sharing an untagged occurrence identity with a withdrawn private Timer. Error preparation and actual cancellation agree; deadline firing passes the complete retained checker, which rejects a forged completion of the survivor. Programs and both states are structurally valid; no profile reachability is claimed.

The [regional incident tests](test/internal-transition-regional-incident.test.ts) preserve or remove a suspended effect and its exact local-data scope together. All four regional families preserve an outside incident; Error/Terminate also remove a contained incident. Six constructed runtime-valid cases check projection, Process data, every issuance collection, and sixteen injected cleanup faults. The wider composition does not admit incident reporting or a source profile.

The [regional position tests](test/internal-transition-regional-position.test.ts) exercise both child-cancellation dispositions beside independent Call or child work. Four constructed cases preserve exact process roots, Call records, and control state, while the position oracle rejects missing roots, broken parent links, orphaned tokens, duplicate scopes, and missing Call records. Removing the hosting root without changing running control is also rejected. These cases establish no broader source admission.

The [Call position tests](test/internal-transition-regional-call-position.test.ts) construct two three-edge Call paths with complete derived instance identities. Actual caller-selected cleanup removes either branch's two nested Calls and preserves the independent path, root association, tokens, and Call counters. Missing incoming links or roots, duplicate Calls, and retained deleted references fail validation. These runtime-valid graphs do not establish nested invocation or source reachability.

The [continuation position tests](test/internal-transition-regional-continuation-position.test.ts) distinguish valid Return/Complete/Error continuation tokens from tokens at a declared foreign-scope place or an undeclared place. Raw helpers lack a Program input, so position projection independently rejects those wrong bindings while the same scope and Call cleanup succeeds; the documented subset defect validator does not own token binding. Actual regional preparation rejects both substituted operation payloads and bad output bindings inserted into the Program, while retaining valid continuations. It also rejects substituting a called root for hosting-root completion. Error retains its parent and caller associations and refuses a handler attached to the wrong scope. Constructed Programs remain outside profile admission. The containing-region removal tests additionally execute hosting-root completion after Terminate and check its empty terminal position.

The [local-control preparation tests](test/internal-transition-local-control-preparation.test.ts) compare retained patches and instantiated publications with actual single operations, exercise sixteen helper-level opposite-order pairs, and reject stale preparations and unsafe output multiplicity.
