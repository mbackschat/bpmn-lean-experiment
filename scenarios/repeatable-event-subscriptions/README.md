# Repeatable Event subscription scenarios

These answer-free scenarios use the [bounded subscription profile](../../profiles/bpmn-2.0.2-repeatable-event-subscriptions-draft/README.md) to review an application while independent audit proceeds. Each model supplies a complete business outcome, including review cancellation, exact subscription withdrawal, surviving outside work and archival completion. Related models retain the existing `subprocess-termination` clone family; source variants do not inflate independent business-family reach.

| Model | Scenario inputs | Business purpose |
|---|---|---|
| [Repeated Message reminders](boundary-message.bpmn) | [Two reminders](boundary-message-repeat.scenario.json), [review completion first](boundary-message-completion-first.scenario.json) | Preserve review and overlapping response work, then withdraw the reminder subscription and reject stale delivery. |
| [Recurring reviewer deadline](boundary-timer.bpmn) | [Two deadlines](boundary-timer-repeat.scenario.json), [review completion first](boundary-timer-completion-first.scenario.json) | Issue fresh periodic reminders while review stays active and finish existing responses after future deadlines are withdrawn. |
| [Recurring review-region deadline](subprocess-boundary-timer.bpmn) | [Two deadlines](subprocess-boundary-timer-repeat.scenario.json), [region completion first](subprocess-boundary-timer-completion-first.scenario.json) | Stop review-region work while preserving parent-owned responses, audit and archival work. |
| [One-shot review-region deadline](subprocess-boundary-one-shot.bpmn) | [Deadline then region completion](subprocess-boundary-one-shot-fire.scenario.json) | Escalate review once and retain the parent-owned response after the region closes. |
| [Audit reminders beside review](message-host-with-child-entry.bpmn) | [Reminders across child termination](message-host-with-child-entry-repeat.scenario.json) | Preserve the outside audit subscription when the child review region terminates, then finish its responses. |
| [Application response catch](catch-message.bpmn) | [Response before cancellation](catch-message-resume.scenario.json), [cancellation before response](catch-message-cancel.scenario.json) | Consume or withdraw the exact response subscription and refuse a stale response without affecting outside work. |
| [Review deadline catch](catch-timer.bpmn) | [Deadline before cancellation](catch-timer-resume.scenario.json), [cancellation before deadline](catch-timer-cancel.scenario.json) | Resume or withdraw the review wait while audit continues. |
| [Document Receive Task](receive-task.bpmn) | [Documents before cancellation](receive-task-resume.scenario.json), [cancellation before documents](receive-task-cancel.scenario.json) | Consume or withdraw an exact direct-Message wait and complete remaining audit and archival work. |

Every scenario binds exact XML bytes and the profile, supplies neutral commands and requested observations, and contains no expected result. Timer commands use the native firing identity for the exact committed occurrence and logical deadline; the runner waits for native Timer progress rather than injecting those commands. The [pipeline catalog](../../packages/differential/test/repeatable-subscriptions-pipeline-cases.ts) owns comparator-side mutations for handler multiplicity, recurring Timer identity, Message lifetime and withdrawal. Direct-VM and live recovery evidence for co-ready races and continuation remain owned by the [capsule](../../docs/capsules/REPEATABLE-EVENT-SUBSCRIPTIONS-SPEC.md).

The CIB provenance is limited to the reused User Task premise at revision `5a45b47ea22688d774de97277c3ff7013f54fdd2`, through `engine/src/main/java/org/cibseven/bpm/engine/impl/bpmn/behavior/UserTaskActivityBehavior.java`. No CIB subscription execution target is selected. The models remain engine regression cases until a complete production-backed browser journey establishes catalog eligibility.
