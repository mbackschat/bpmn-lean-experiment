# Interrupting Activity boundary Timer scenarios

This directory contains one exact BPMN 2.0.2 source and two answer-free scenarios for the [interrupting Activity boundary Timer capsule](../../docs/capsules/ACTIVITY-BOUNDARY-TIMER-SPEC.md). The [activity-wins scenario](activity-wins.scenario.json) completes the bounded User Task before its deadline and then its normal follow-on task. The [deadline-wins scenario](deadline-wins.scenario.json) fires the exact `PT1S` deadline and then completes the boundary follow-on task instead. One bounded User Task owns one interrupting `PT1S` Timer Boundary Event, and each route reaches its own follow-on User Task, which is what makes the route choice observable at the public boundary. Two further scenarios are excluded with their reasons in the specification: the abandoned Activity’s stale completion, because neither admitted delivery mode preserves the order it depends on, and a pre-due firing, because the host derives its firing instant from the wait’s own committed deadline so no target can present an off-deadline one.

`cancelActivity` is deliberately omitted from the source rather than written as `true`. The XSD and CMOF default it to `true`, so omission is the admissible interrupting form; lexical `false` is a separate proposition and is rejected.

Lean, the independently implemented TypeScript semantic core, and the Temporal adapter all execute this source and agree on both scenarios. No CIB boundary-Timer relationship, target, or retained evidence is selected. Target inputs added here must carry no winner annotation and no expected result.
