# Concurrent embedded activation sources

This directory contains three exact BPMN 2.0.2 sources for the [concurrent embedded activations proposal](../../docs/capsules/CONCURRENT-EMBEDDED-ACTIVATIONS-PROPOSAL.md). In each one, a Parallel fork's User Task branches meet at an identity-only converging Exclusive Gateway that feeds an embedded Sub-Process, so every arriving branch starts its own concurrent activation of that Sub-Process. Clause 13.4.2 passes each arriving token through the merge on its own, and Clause 13.3.4 instantiates the Sub-Process for every arriving token. That is the mechanism these sources witness.

- The [audit remediation source](audit-remediation.bpmn) reviews controls and payments in parallel inside an Audit Sub-Process. Each finding opens its own Remediation with Fix finding and Verify fix, then reports its finding, and the root closes the audit once the Audit scope quiesces.
- The [credit intake source](credit-intake.bpmn) opens an application and then runs three checks in parallel. Each check reaches its own Assess activation, which scores the applicant, and the root decides after the Intake scope quiesces.
- The [claim escalation source](claim-escalation.bpmn) places the region in a depth-2 Review body whose target, Escalation, sits at depth 3. File case and Close claim follow in the enclosing scopes.

The bounded profile admits these shapes. The focused [source-admission test](../../packages/bpmn-source/test/concurrent-embedded-activations-source-admission.test.ts) drives the audit and intake journeys through the semantic core in both completion orders, including a stale command addressed to a completed activation, and it locks the refused near-miss shapes. The answer-free schedules follow the capsule's semantic checkpoint and are not registered yet.
