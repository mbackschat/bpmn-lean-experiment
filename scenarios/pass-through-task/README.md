# Pass-through Task scenarios

The [pass-through Task specification](../../docs/capsules/PASS-THROUGH-TASK-SPEC.md#separating-witnesses) owns the bounded account; both models are witnesses for the [nested scope-data profile](../../profiles/cibseven-2.2.0-nested-embedded-scope-data-draft/profile.json), each with an exact source overlay binding its one Service Task to a caller-supplied Activity handler.

- The [equipment return](equipment-return.bpmn) with its [handler](equipment-return-overlay.json) schedules a pickup, inspects the returned equipment in a Sub-Process whose Manual Task *Unpack equipment* precedes the User Task *Record condition*, refunds the deposit and closes the return through the plain Task *Close return ticket*.
- The [document intake](document-intake.bpmn) with its [handler](document-intake-overlay.json) classifies a received document in a Sub-Process whose User Task *Record document format* sets the Sub-Process's own `format`, copied out to `documentFormat`, and branches on it: a paper document is archived in a Sub-Process whose Manual Task *File paper original* precedes the Service Task *Index archive location*, an illegible one passes the Manual Task *Phone sender for a better copy* and is classified again with a fresh `format`, and any other format passes the plain Task *Register digital copy*. The classification sits in a Sub-Process because the profile admits a User Task completion only over names a frame on its chain declares.

The [source test](../../packages/bpmn-source/test/pass-through-task-source.test.ts) compiles both models and locks the refused one-fact edits. The [CIB calibration probe](../../runners/cibseven/src/test/java/org/bpmnlean/cibseven/CibSevenPassThroughTaskProbeTest.java) drives both models in CIB Seven `2.2.0`, with each condition rendered as JUEL.

Three answer-free schedules are registered as standards-only pipeline cases by the [pipeline cases](../../packages/differential/test/pass-through-task-pipeline-cases.ts), each with one seeded mutation that lets a pass-through Task wait as a User Task. Their occurrences appear only in the command publications, which the [publication agreement test](../../packages/differential/test/pipeline-publication-lean-core.integration-test.ts) compares between Lean and the core:

- [Equipment return](equipment-return.scenario.json) schedules the pickup, records the condition and completes the refund. Its mutation leaves *Unpack equipment* open in place of *Record condition*.
- [Intake, illegible twice then paper](intake-illegible-twice-then-paper.scenario.json) phones the sender twice, re-entering the classification each time, then archives the paper original. Its mutation leaves *Phone sender* open in place of the second classification.
- [Intake, digital](intake-digital.scenario.json) registers the digital copy and ends. Its mutation leaves the Process running after the classification.
