# Concurrent mapped Calls sources

This directory contains the exact BPMN 2.0.2 sources of the [concurrent mapped Calls specification](../../docs/capsules/CONCURRENT-MAPPED-CALLS-SPEC.md). Each places Call Activities with `camunda:in` and `camunda:out` mappings on concurrent Parallel branches of the embedded completion profile, so every call reads its inputs from, and writes its outputs to, its own caller occurrence's chain.

- The [supplier onboarding source](supplier-onboarding.bpmn) forks into a Financial review and a Compliance review Sub-Process. Each declares a local file and a pending verdict, prepares the file and then asks one reusable Expert opinion Process, the financial call mapping the file in as `dossier` and `opinion` out to the verdict, the compliance call mapping it in as `screeningFile` and `finding` out. Each review publishes its verdict to the Process before the supplier is approved.
- The [travel request source](travel-request.bpmn) forks straight into a Budget check Call, a Visa check Call and a Booking Sub-Process whose local budget starts from the pre-approved budget. Each Call maps the traveller in; Budget check maps its confirmed budget out to `approvedBudget` and Visa check its decision to `visaStatus`.

The focused [source test](../../packages/bpmn-source/test/concurrent-mapped-calls-source.test.ts) compiles both sources as data-bearing Programs, derives their required and optional Start names and locks the refused source mutations; the [runtime test](../../packages/bpmn-source/test/concurrent-mapped-calls-runtime.test.ts) reads each call's frame in committed state.

Three answer-free schedules are registered as standards-only pipeline cases, each with one seeded mutation; the [pipeline-case test](../../packages/differential/test/concurrent-mapped-calls-pipeline-cases.test.ts) runs the others:

- [Supplier, compliance expert first](supplier-compliance-first.scenario.json) prepares both files, refuses each expert's patch of the other Call's output, the financial task under the compliance identity and the compliance task after its return, and lets the compliance expert answer before the financial one. Its mutation commits the compliance expert's patch of the financial output source `opinion`, as selecting the called-root mappings by called definition would.
- [Supplier, financial expert first](supplier-financial-first.scenario.json) lets the financial expert revise its `dossier` and answer first, so only its review's verdict reaches the Process, and refuses the compliance task under the caller's identity. Its mutation publishes the financial review's initial `pending` verdict and puts `verdict` in the Process, as writing the output from the hosting root would.
- [Travel request](travel-request.scenario.json) starts with the approved budget and no traveller, so one Start batch invokes both checks and enters Booking, then the budget check confirms a lower budget and the visa check grants the visa. Its mutation rolls the Start back, as leaving mapped invocations on the singleton path would.
