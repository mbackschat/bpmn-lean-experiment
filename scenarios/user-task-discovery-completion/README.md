# User Task discovery and completion scenarios

This capsule owns one exact content-addressed [BPMN Process](process.bpmn) and three answer-free semantic witnesses.

The [exact-completion scenario](scenario.json) starts with canonical `requestTitle = "Review invoice 42"`, observes that Process binding and one active task named `Approve` with semantic occurrence identity `(Instance_1, UserTask_Approve, 1)`, exposes a command-ID-free completion capability, completes that occurrence with a second canonical patch, and observes Process completion with all committed values. Its CIB answer is retained separately in [cibseven-evidence.json](cibseven-evidence.json).

The [wrong-activation scenario](wrong-activation.scenario.json) submits activation ordinal `2`. It is rejected before host-task completion, and the ordinal-`1` task remains active. Its answer is retained in [wrong-activation.cibseven-evidence.json](wrong-activation.cibseven-evidence.json).

The [stale-completion scenario](stale-completion.scenario.json) completes the exact occurrence and then submits another command for that completed occurrence. The second command is rejected and the completed state remains unchanged. Its answer is retained in [stale-completion.cibseven-evidence.json](stale-completion.cibseven-evidence.json).

All evidence is calibrated through one warm pinned CIB runner and bound to exact scenario and profile bytes. Generated CIB task IDs remain local host mappings. Lean independently derives all three traces and proves full-occurrence mismatch rejection with state preservation plus an element-only identity non-law. The TypeScript semantic core independently derives the same results. Temporal exposes the core-owned task projection through Query, returns accepted command outcomes through Update, checks duplicate logical delivery, and replays each live history before the disposable server shuts down. For the stale scenario, Temporal agrees exactly through semantic completion and separately returns adapter-owned `processClosed` after the explicit post-terminal delivery schedule; CIB Seven, Lean, and the core retain the full semantic rejection trace unchanged. The batch also detects a seeded activation mutation.

The [CIB–BPMN relationship register](../../docs/CIB-BPMN-RELATION-REGISTER.md) classifies task discovery and completion as bounded agreement (`CIB-AGR-0002`), public Process-start data as selected extension `CIB-EXT-0006`, public completion data as selected extension `CIB-EXT-0005`, and the generated-ID-to-semantic-occurrence bridge as operational mapping `CIB-OP-0001`. The complete meaning and exclusions are owned by the [User Task interaction capsule](../../docs/capsules/USER-TASK-INTERACTION-SPEC.md), [Process-start data specification](../../docs/capsules/PROCESS-START-DATA-SPEC.md), and [completion-data specification](../../docs/capsules/USER-TASK-COMPLETION-DATA-SPEC.md).
