# Competing Conditional items

Answer-free schedules for [PC-CONDITION-03](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list) and [PC-CONDITION-04](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list): Conditional items true at one evaluation where firing one withdraws another. Two interrupting boundaries of one host on every kind of host, two interrupting Event Sub-Process starts of one scope, an interrupting and a non-interrupting item of one host or scope, nested cancellation regions, a host's boundary with an Event Sub-Process start of the scope it opens, and Event-Based arms under the standards profile. A contest arises when a host is entered with its predicates already true and when one write, a completion's values or an effect result's outputs make them true together. BPMN gives simultaneous triggers no order and CIB takes one that no profile selects, so the input's ranking `conditionChoices` decides each contest and a contest it leaves undecided is refused ([CIB-LIM-0053](../../../docs/CIB-BPMN-RELATION-REGISTER.md#cib-lim-0053--competing-conditional-items-true-at-one-evaluation-fire-in-the-inputs-ranked-order-which-cib-cannot-be-given)). The [subscriptions semantics](../../../docs/kernel/semantics/SUBSCRIPTIONS-SEMANTICS-SPEC.md#conditions) own the meaning. The models are project-authored MIT source with no source overlay.

## Notes for the target runners

- `items` is the String list `a, b` in every schedule on `competing-hosts`; the standards schedules and `two-writes-first-wins` start no variable. A body is addressed by activation, counted per begun occurrence.
- A write is addressed to the open Human Task occurrence whose scope it is written in; `Fetch` is answered by `effectResult` with its output `figureNext`.
- A ranking that puts a firing before an interruption of the region where that firing's handler continues is refused (`interrupted-before-wait`, [CIB-LIM-0055](../../../docs/CIB-BPMN-RELATION-REGISTER.md#cib-lim-0055--work-an-earlier-firing-started-that-a-later-interruption-would-remove-before-its-first-wait-is-unsupported)): the kernel would remove the region before the handler reaches its first wait, where CIB runs the handler there first. So `esp-mixed-warn-then-stop`, `nested-inner-then-outer`, the `enabled-*-start-then-boundary` schedules and their standards twins end at the refused input; the interrupting member first commits under every profile (`esp-mixed-stop-first`, `nested-outer-first`, `enabled-*-boundary-first`, `standards-mixed-stop-first`, `standards-nested-outer-first`, `standards-enabled-boundary-first`), and so does `standards-mixed-warn-then-stop`, whose non-interrupting boundary's handler continues outside its host.
- A host's boundaries and the Event Sub-Process starts of the scope it opens are one evaluation (`enabled-*`): the ranking, not the arming order, decides which fires.

The schedules carry no expected route, open wait, variable or Process state. Every schedule but `two-writes-first-wins` and the three `pending-*-no-choice` carries a ranking or raises a contest that needs one, which the CIB runner cannot be given, and names no CIB revision (`not-applicable`), so the differential compares the Lean kernel with the TypeScript kernel on it. In those four no contest needs a ranking, since an earlier write's pending interrupting firing decides it, so they name the pinned CIB revision: `two-writes-first-wins` has its retained answer, which agrees with the kernel, and the three `pending-*-no-choice` await theirs.
