# Call binding across deployments

Population witnesses of [PC-SCOPE-03](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list)'s program assembly: a deployment carries a renamed copy of each other deployment's process its Calls name, and publication and addressing still use the identifiers the callee's author wrote.

- [Copied callee boundary](copied-callee-boundary.population-scenario.json) deploys the [assessment](assessment.bpmn) as deployment 1 and the [intake](intake.bpmn), whose Call names `assessment:AssessClaim` in the assessment's namespace, as deployment 2. The intake's program carries the assessment's process as a copy whose element and boundary identifiers are renamed for deployment 1. The schedule starts a claim and fires the timer boundary *Review overdue* of the called instance's *Review the claim* by its authored identifier.
- [Nested callee binds at its own deployment](nested-callee-binds-at-own-deployment.population-scenario.json) deploys the [first review](review-first.bpmn), the [triage](triage.bpmn) whose Call names `review:ReviewDamage`, the [second review](review-second.bpmn) of the same key and the [damage claim](damage-claim.bpmn) whose Call names the triage, then starts a claim. The claim's program carries both reviews, but the triage's Call binds at the triage's deployment 2, so the called review waits in *Inspect the photos* of version 1. Under this `bpmn-2.0.2` witness CIB reads the prefixed `calledElement` as a key text and rolls the start back ([CIB-EXT-0045](../../../docs/CIB-BPMN-RELATION-REGISTER.md#cib-ext-0045--a-call-names-its-callee-by-key-text-and-binds-a-deployment-a-version-or-a-version-tag)); its [key-text variant](nested-callee-binds-at-own-deployment-key-text.population-scenario.json) carries the same schedule under `cibseven-2.2.0`.
- [Nested callee binds at its own deployment, key text](nested-callee-binds-at-own-deployment-key-text.population-scenario.json) is that schedule under `cibseven-2.2.0` over the [triage](triage-key.bpmn) and the [damage claim](damage-claim-key.bpmn) with unprefixed `calledElement` values (`ReviewDamage`, `TriageDamage`), which CIB reads as the key text of a deployed process, and the same two reviews. It separates the binding time of [CIB-INT-0034](../../../docs/CIB-BPMN-RELATION-REGISTER.md#cib-int-0034--cib-binds-a-calls-callee-at-each-invocation): the kernel binds the triage's Call among the reviews deployed no later than the triage, while CIB's default `latest` binding looks the review up when the Call is reached, after the second review is deployed.
- [Carried call cycle](carried-call-cycle.population-scenario.json) deploys the [escalation loop](escalation-loop.bpmn), whose root calls *Escalate*, which calls *Appeal*, which calls *Escalate* again; the deployment is refused as `work.call.cycle`, where CIB deploys it and starts a new instance per invocation. Per-caller eligibility makes such a cycle possible only among processes of one deployment: a process binds only callees deployed no later than itself.

No expected result appears in target input; the CIB runner's population mode produces their CIB evidence, compared with the kernel at CIB's observation boundary.
