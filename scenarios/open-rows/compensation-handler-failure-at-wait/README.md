# Compensation handler failure at a wait

This directory serves [PC-COMPENSATION-01](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list) and [PC-COMPENSATION-04](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list): what an Error or an Escalation that a compensation handler raises after it has waited does to the compensation run, to its trigger and to the catchers around the compensated Sub-Process; the failure paths of [PC-TX-02](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list) are the same question under a Transaction. The models are project-authored MIT source for the `cibseven-2.2.0` profile and, through the `-standards` schedules, for the [`bpmn-2.0.2` profile](../../../profiles/bpmn-2.0.2/README.md); `error-esp-handler` has only a `-standards` schedule. Every schedule is answer-free and CIB Seven `2.2.0` supplies the retained answer for the `cibseven-2.2.0` ones.

## Models

The first four models differ only in what the handler raises and in whether a catcher exists. The Sub-Process `SubProcess_Outer` runs the Sub-Process `SubProcess_Work` (the User Task `UserTask_Work`). A Compensation Boundary Event on `SubProcess_Work` is associated with the Sub-Process `SubProcess_Undo`, which runs the User Task `UserTask_UndoReview` into an End Event that raises the Error `UNDO_FAILED` or the Escalation `UNDO_ESCALATED`. After `SubProcess_Work`, an untargeted Intermediate Compensation throw leads to `UserTask_After`; `SubProcess_Outer` then leads to `UserTask_Settle`. The Process has no other handler.

| Model | Raised by the handler | Catcher |
|---|---|---|
| [error-caught](error-caught.bpmn) | Error End Event | Error Boundary Event on `SubProcess_Outer` for the same code, leading to `UserTask_Caught` |
| [error-uncaught](error-uncaught.bpmn) | Error End Event | none |
| [escalation-caught](escalation-caught.bpmn) | Escalation End Event | interrupting Escalation Boundary Event on `SubProcess_Outer` for the same code, leading to `UserTask_Caught` |
| [escalation-uncaught](escalation-uncaught.bpmn) | Escalation End Event | none |
| [escalation-relayed](escalation-relayed.bpmn) | an Intermediate Escalation throw after `UserTask_UndoReview`, caught by `SubProcess_Undo`'s own non-interrupting Escalation Event Sub-Process, which throws it again before `UserTask_Note`; `SubProcess_Undo` then waits at `UserTask_UndoConfirm` | non-interrupting Escalation Boundary Event on `SubProcess_Outer` for the same code, leading to `UserTask_Caught` |

The [escalation-group-subject](escalation-group-subject.bpmn) model has a different shape. Its Sub-Process `SubProcess_Subject` has no handler of its own: it runs `UserTask_Work`, whose Compensation Boundary Event is associated with `SubProcess_Undo`, which runs `UserTask_UndoReview` into an Escalation End Event for `UNDO_ESCALATED`. `SubProcess_Subject` carries a non-interrupting Escalation Boundary Event for the same code, leading to `UserTask_CaughtAtSubject`, and the Process declares a non-interrupting Escalation Event Sub-Process for it, leading to `UserTask_CaughtAtProcess`. After `SubProcess_Subject`, an untargeted Intermediate Compensation throw leads to `UserTask_After`, so the throw compensates the completed Sub-Process as its records' group and `SubProcess_Undo` runs inside that group's compensation context.

The [error-esp-handler](error-esp-handler.bpmn) model compensates through a Compensation Event Sub-Process. The Sub-Process `SubProcess_Subject` runs `UserTask_Work` and declares the Compensation Event Sub-Process `EventSubProcess_Undo`, whose body is `start -> UserTask_UndoReview -> End Event` raising the Error `UNDO_FAILED`. After `SubProcess_Subject`, an untargeted Intermediate Compensation throw leads to `UserTask_After`. Nothing catches the Error.

Three models place the raising handler where its model scopes and its compensation trigger's scopes differ ([#159](https://github.com/mbackschat/bpmn-lean-experiment/issues/159)). In [escalation-esp-handler](escalation-esp-handler.bpmn) the Sub-Process `SubProcess_Subject` runs `UserTask_Work` and declares the Compensation Event Sub-Process `EventSubProcess_Undo`, which runs `UserTask_UndoReview` into an Escalation End Event for `UNDO_ESCALATED`; `SubProcess_Subject` carries a non-interrupting Escalation Boundary Event to `UserTask_CaughtAtSubject`, the Process declares a non-interrupting Escalation Event Sub-Process to `UserTask_CaughtAtProcess`, and an untargeted Process-level Intermediate Compensation throw follows `SubProcess_Subject` before `UserTask_After`. Its Compensation start declares no `isInterrupting`, which BPMN 2.0.2 Table 10.87 does not apply to it. [plain-esp-handler](plain-esp-handler.bpmn) is the same model with a none End Event in place of the Escalation End Event. In [escalation-trigger-esp](escalation-trigger-esp.bpmn) the Process-level `UserTask_Work` has a Compensation Boundary Event associated with the Sub-Process `SubProcess_Undo` (`UserTask_UndoReview`, then an Escalation End Event for `UNDO_ESCALATED`) and leads to `UserTask_Hold`; the Process's non-interrupting Message Event Sub-Process `EventSubProcess_Trigger` (Message `compensateWork`) throws Compensation at `UserTask_Work` and then waits at `UserTask_AfterThrow`, and declares its own non-interrupting Escalation Event Sub-Process to `UserTask_CaughtInTriggerEsp`; the Process declares a non-interrupting Escalation Event Sub-Process to `UserTask_CaughtAtProcess`.

## Schedules

Each schedule completes `UserTask_Work` (the subject completes and the throw follows), completes the handler's `UserTask_UndoReview`, and then addresses what could follow: `UserTask_After`, `UserTask_Settle` and, in the caught variants, `UserTask_Caught`. A stimulus that addresses a wait that is not open is part of the schedule, not a mistake in it.
