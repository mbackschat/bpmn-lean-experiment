# Booking recovery journey: a failed child, Transaction cancellation and compensated reservations

Answer-free schedules for [PC-JOURNEY-07](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list): a trip booking reserves a flight, a hotel room and a rental car inside one Transaction while an agent may cancel the booking. A failed car reservation reaches the recovery scope nearest to it that matches its Error, and a cancellation compensates the reservations that completed, waits for every required handler before the cancellation path continues, and leaves unfinished work uncompensated and unrevivable. Each schedule pairs an ordinary path with the nearest wrong-scope, unfinished-work, wrong-context, skipped-handler or late-resurrection case. The [compensation](../../../docs/kernel/semantics/COMPENSATION-SEMANTICS-SPEC.md), [propagation](../../../docs/kernel/semantics/PROPAGATION-SEMANTICS-SPEC.md) and [scopes](../../../docs/kernel/semantics/SCOPES-SEMANTICS-SPEC.md) semantics own the meaning; the schedules only exercise it. The profile is `cibseven-2.2.0`.

Five steps are named business handlers, `reserveFlight`, `cancelFlight`, `reserveRoom`, `confirmRoom` and `releaseRoom`, that the exact [source overlay](booking-overlay.json) binds to neutral effect descriptors; the model carries no probe handler and no scenario names a model identity, so a host binds the same names through its own configuration (PC-AUTO-01). Every schedule therefore names no CIB revision (`cibRevision` is `not-applicable`): the CIB runner registers only the three delegate tokens of `CibSevenScriptedEffect.HANDLER_BEANS`, so it cannot run a model whose handlers carry these names. Retained CIB evidence for this journey needs a runner that registers the five tokens, or a calibration probe that registers them as delegate beans; the constructs it combines have their own CIB witnesses ([transaction-cancel-mixed](../transaction-cancel-mixed/README.md), [transaction-cancel-waiting-handlers](../transaction-cancel-waiting-handlers/README.md), [transaction-and-error-exits](../transaction-and-error-exits/README.md), [compensation-context](../compensation-context/README.md), [compensation-effect-and-call-records](../compensation-effect-and-call-records/README.md), [error-called-child](../error-called-child/README.md)).

## Model

[booking.bpmn](booking.bpmn) holds two processes in one document, the first being the root.

| Process | What it holds |
|---|---|
| `Process_Booking` | Starts with the String `bookingId`, the Maps `traveler` (`name`, `email`) and `route` (`from`, `to`, `date`), the Integer `nights`, the String `roomPreference` and the Strings `roomRef`, `roomType`, `flightRef` and `carRef` at placeholder values. The Transaction *Book the trip* forks four branches. *Reserve the flight* (named handler `reserveFlight`, asynchronous before) writes `flightRef` and has a Compensation Boundary Event with the handler *Cancel the flight* (`cancelFlight`, reading `flightRef` and `bookingId`). The Sub-Process *Reserve the hotel* declares the locals `roomRef` (`unassigned`) and `roomType` (from `roomPreference`), runs *Reserve the room* (`reserveRoom`) and then *Confirm the room* (`confirmRoom`), each writing `roomRef`, and holds a Compensation Event Sub-Process whose Service Task *Release the room* (`releaseRoom`) reads `roomRef` and `roomType`. The Call *Reserve the car* of `Process_CarRental` maps `bookingId` and `traveler` in and `carRef` out, has a Compensation Boundary Event with the Human Task *Cancel the car at the rental desk* (`agents`), and an interrupting Error Boundary Event `NO_CAR` to the Human Task *Offer another car class* (`agents`). The Human Task *Decide whether to keep the booking* (`agents`) writes `bookingDecision`, and an Exclusive Gateway sends `cancel` to a Cancel End Event and otherwise to a None End Event. The Transaction has a Cancel Boundary Event leading to the Human Task *Tell the traveler the booking is cancelled* (`agents`), an Error Boundary Event `CARD_DECLINED` leading to the Human Task *Handle the payment failure* (`finance`), and a normal exit to the Human Task *Send the itinerary* (`agents`). |
| `Process_CarRental` | The Human Task *Confirm the car with the rental desk* (`rental-desk`) writes `carStatus` and `carRef`. `unavailable` ends in the Error End `NO_CAR`, `declined` in the Error End `CARD_DECLINED` and anything else in a normal End. |

The three reservations are the only compensable subjects, and they share no names: every expression of a subject is a plain variable read, so the kernel finds no data dependency between them, no handler has to wait for another and the three start together. The flight and the car are Activities with a boundary handler, which restores no context and reads the Process variables as they are when it runs; the hotel is a Sub-Process with a Compensation Event Sub-Process, which restores the Sub-Process's own variables as they were when it completed and reads every other name live. The reservations use `FL-4471`, `RM-204` (confirmed as `RM-204-UPG`) and `CR-889`.

## Schedules

Each schedule names the acceptance clause of PC-JOURNEY-07 it witnesses. Every command in a failing schedule that is not the refused one is the valid continuation, so a refusal that leaves the state unchanged is told from one that does not. The handlers are answered in an order that every reading of the compensation order admits, since the three are independent.

| Schedule | Clause witnessed | Case it separates |
|---|---|---|
| [cancel-compensates-completed-reservations](cancel-compensates-completed-reservations.scenario.json) | Transaction cancellation compensates completed reservations; wait for required handlers; skipped handler fails; late resurrection fails | The flight, the room and the car complete and the agent cancels: *Cancel the flight*, *Release the room* (reading the confirmed `RM-204-UPG`, neither the first reference `RM-204` nor the entry value `unassigned`) and *Cancel the car* start together. *Tell the traveler* is refused with all three open and with one open, a repeated decision and repeated flight and room results are refused as the interior is gone, and *Tell the traveler* opens only after the last handler. |
| [handlers-answered-in-another-order](handlers-answered-in-another-order.scenario.json) | Wait for required handlers; skipped handler fails | The same cancellation with the flight handler answered first, then the car's, then the room's: *Tell the traveler* is refused after the first and after the second handler and opens with the third. |
| [late-changes-reach-the-handlers](late-changes-reach-the-handlers.scenario.json) | Wrong frozen context fails | After the reservations a variable command at the open decision task rebooks the flight (`flightRef`) and overwrites `roomRef` and `roomType` at the Process. *Cancel the flight* reads the rebooked reference, since a boundary handler restores nothing; *Release the room* reads `RM-204-UPG` and `double`, the Sub-Process's variables as they were when it completed, not the Process-level overwrites. |
| [cancel-leaves-unfinished-work-uncompensated](cancel-leaves-unfinished-work-uncompensated.scenario.json) | Unfinished-work compensation fails; late resurrection fails | The flight is complete, the room is reserved but not confirmed and the car is open when the agent cancels: only *Cancel the flight* starts. The room confirmation, the car confirmation, and results for *Release the room* and *Cancel the car*, which never started, are refused; *Tell the traveler* is refused while the flight handler is open and opens after it, and the late room and car results are refused again. |
| [cancel-while-reservations-are-still-open](cancel-while-reservations-are-still-open.scenario.json) | Unfinished-work compensation fails; late resurrection fails | The agent cancels before any reservation completed, so nothing is compensated and *Tell the traveler* opens at once. The flight, room and car results that arrive afterwards and results for the two handlers that never started are refused. |
| [no-car-recovered-at-the-call-boundary](no-car-recovered-at-the-call-boundary.scenario.json) | A failed child routes to the correct (nearest) recovery scope; wrong scope fails | The rental desk reports `unavailable`: the called instance raises `NO_CAR`, which the Call's boundary takes, so *Offer another car class* opens and the Transaction goes on. *Handle the payment failure*, a late car confirmation and *Cancel the car* are refused; the flight and the hotel complete, the decision is `keep`, *Send the itinerary* is refused while the offer is open and opens after it. |
| [card-declined-reaches-the-transaction-boundary](card-declined-reaches-the-transaction-boundary.scenario.json) | A failed child routes to the correct (outer) recovery scope; wrong scope fails; late resurrection fails | The flight is complete and the room awaits its confirmation when the desk reports `declined`. No boundary of the Call matches `CARD_DECLINED`, so the Transaction's Error boundary takes it, removes the interior and opens *Handle the payment failure*; an Error is no cancellation, so no handler starts. *Cancel the flight*, the room confirmation, the decision, *Offer another car class* and *Tell the traveler* are refused. |
| [cancel-after-the-car-recovery](cancel-after-the-car-recovery.scenario.json) | Cancellation compensates completed reservations only; skipped handler and unfinished-work compensation fail | The car failed with `NO_CAR` and its recovery finished, the flight and the hotel completed and the agent cancels: *Cancel the flight* and *Release the room* start, the failed car left no record so *Cancel the car* is refused, and *Tell the traveler* is refused until both handlers finished. |
| [booking-kept-without-compensation](booking-kept-without-compensation.scenario.json) | Ordinary completion starts no handler | Every reservation completes and the decision is `keep`: the Transaction completes normally and opens *Send the itinerary*. Results for the three handlers and *Tell the traveler* are refused, and *Send the itinerary* completes the Process. |

Notes for the target runners:

- A handler is an occurrence of its own element, addressed as activation 1 of `CancelFlight`, `ReleaseRoom` or `CancelCar`. The called instance of the car reservation is addressed by the kernel's derived identity, `call:9:Booking_1:10:ReserveCar:1`.
- Every effect result is a scenario `effectResult` stimulus, so no handler runs: the host supplies the five named handlers through its own configuration, and the stimulus carries each result as scalar outputs (`flightReference`, `roomReference`, `confirmedReference`) that the model's output mappings read. The three compensation handlers' results carry no outputs.
- An Error that a Transaction's boundary takes is no Cancel: the interior is removed and its records dropped, as in [transaction-and-error-exits](../transaction-and-error-exits/README.md).
- The schedules answer handlers and address the interior in orders that leave refused commands unchanged, so the refusals are part of the schedule rather than harness mistakes.
- The schedules carry no expected eligible set, open wait, variable or Process state.
