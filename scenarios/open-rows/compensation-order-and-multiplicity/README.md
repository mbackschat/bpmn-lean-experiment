# Compensation order and handler multiplicity

This directory serves [PC-COMPENSATION-01](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list) (the order in which an untargeted throw invokes handlers) and [PC-COMPENSATION-03](../../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list) (how many handlers a looping Activity leaves): a Sequence Flow path through nodes that have no handler, a boundary path that leaves compensable work, Multi-Instance Call Activities, a Multi-Instance Human Task that a completion condition ends early, and a Multi-Instance Human Task over zero and over two items under both profiles. The models are project-authored MIT source; the Multi-Instance models that carry `camunda:` attributes select `cibseven-2.2.0` only, [user-parallel-handler-standards](user-parallel-handler-standards.bpmn) is the standards form for the [`bpmn-2.0.2` profile](../../../profiles/bpmn-2.0.2/README.md), and the two path models run under both. Every schedule is answer-free and CIB Seven `2.2.0` supplies the retained answer for the `cibseven-2.2.0` ones.

## Models

| Model | Shape |
|---|---|
| [path-without-handler](path-without-handler.bpmn) | `UserTask_A` (handler `UserTask_UndoA`), then `UserTask_Between` without a handler, then an Exclusive Gateway with one outgoing flow, then `UserTask_B` (handler `UserTask_UndoB`), an untargeted throw and `UserTask_After`. |
| [boundary-path-handler](boundary-path-handler.bpmn) | The Sub-Process `SubProcess_A` (User Task `UserTask_InA`) has a Compensation Boundary Event (handler `UserTask_UndoA`) and a non-interrupting Message Boundary Event for `note` leading to `UserTask_B` (handler `UserTask_UndoB`). `SubProcess_A` leads to an untargeted throw and `UserTask_After`. |
| [call-parallel](call-parallel.bpmn), [call-sequential](call-sequential.bpmn) | They differ only in `isSequential`. The Call Activity `CallActivity_Review` of `Process_Review` (Human Task `UserTask_Check`) runs over the collection `reviewers` with the element variable `reviewer`. A Compensation Boundary Event on it is associated with `UserTask_UndoReview` (input `seenReviewer` reads `reviewer`). Then `UserTask_Pause`, an untargeted throw and `UserTask_After`. |
| [user-parallel-quorum](user-parallel-quorum.bpmn) | The parallel Multi-Instance Human Task `UserTask_Review` over `items` with the element variable `item` and the completion condition `${nrOfCompletedInstances >= 1}`; a Compensation Boundary Event is associated with `UserTask_UndoReview`. Then `UserTask_Pause`, an untargeted throw and `UserTask_After`. |
| [user-parallel-handler](user-parallel-handler.bpmn) | The same Human Task without a completion condition. |
| [user-parallel-handler-standards](user-parallel-handler-standards.bpmn) | The same shape in the standards form: the Property `items`, a Data Input Association feeding the loop, no `camunda:` attribute. |

## Schedules

| Schedule | Model | Journey | Question it separates |
|---|---|---|---|
| [later-handler-first](later-handler-first.scenario.json), [-standards](later-handler-first-standards.scenario.json) | path-without-handler | `UserTask_A`, `UserTask_Between` and `UserTask_B` complete; `UserTask_UndoA` is addressed before `UserTask_UndoB`, then again; then `UserTask_After`. | Does the Sequence Flow path through a Task without a handler and a Gateway order B's handler before A's? |
| [with-message-before-a-completes](with-message-before-a-completes.scenario.json), [-standards](with-message-before-a-completes-standards.scenario.json) | boundary-path-handler | The message `note` is delivered while `SubProcess_A` is active; `UserTask_B` completes; `UserTask_InA` completes; `UserTask_UndoA` is addressed before `UserTask_UndoB`, then again; then `UserTask_After`. | When the boundary fired and its path completed work, is that work compensated before the Sub-Process it left? |
| [without-message](without-message.scenario.json), [-standards](without-message-standards.scenario.json) | boundary-path-handler | `UserTask_InA` and `UserTask_UndoA` complete; the message is delivered after `SubProcess_A` ended; then `UserTask_After`. | Is the boundary gone once its Sub-Process ended, and is only A's handler left? |
| [call-parallel-three-reviewers](call-parallel-three-reviewers.scenario.json) | call-parallel | `reviewers = [r1, r2, r3]`; the called tasks complete in the order 2, 3, 1 (called instances `call:10:Instance_1:19:CallActivity_Review:N`); `reviewer` is set to `late` at `UserTask_Pause`; `UserTask_UndoReview` is addressed with activations 1, 2 and 3; then `UserTask_After`. | How many handlers does a parallel Multi-Instance Call Activity leave, and which data do they read? |
| [call-sequential-three-reviewers](call-sequential-three-reviewers.scenario.json) | call-sequential | The same journey with the called tasks completing in the order 1, 2, 3. | The same question for a sequential one, and whether the handlers follow the reverse of the instances' order. |
| [user-parallel-quorum-ends-after-one](user-parallel-quorum-ends-after-one.scenario.json) | user-parallel-quorum | `items = [a, b, c]`; `UserTask_Review` activation 2 completes and ends the Activity; activations 1 and 3 are addressed afterwards; `UserTask_Pause` completes; `UserTask_UndoReview` is addressed with activations 1 and 2; then `UserTask_After`. | Do instances that the completion condition cancelled leave handlers? |
| [user-handler-zero-items](user-handler-zero-items.scenario.json), [-standards](user-handler-zero-items-standards.scenario.json) | user-parallel-handler, user-parallel-handler-standards | `items = []`; `UserTask_Pause` completes; `UserTask_UndoReview` is addressed with activations 1 and 2; then `UserTask_After`. | Does a Multi-Instance Task over no items leave a handler? |
| [user-handler-two-items](user-handler-two-items.scenario.json), [-standards](user-handler-two-items-standards.scenario.json) | user-parallel-handler, user-parallel-handler-standards | `items = [a, b]`; both instances complete; `UserTask_Pause` completes; `UserTask_UndoReview` is addressed with activations 1 and 2; then `UserTask_After`. | Does a Multi-Instance Task leave one handler for the Activity or one per completed instance? |

The schedules carry no expected handler count, order or Process state; the retained CIB evidence is the answer. The `-standards` schedules select no CIB oracle.
