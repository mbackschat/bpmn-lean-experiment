# Expense exception review scenarios

The three answer-free schedules use one content-addressed [expense exception review source](process.bpmn). The Process starts with no variables, opens `ReviewException` for literal candidate group `reviewers`, and completes it with one atomic patch before the existing Simple Boolean String-equality gateway, reading `Property_Resolution`, selects Approved, Changes requested, or the default Aborted end. `ReviewException` declares one standard Data Output per submitted name, the seven form field keys and `resolution`, each with its key as its id, in one OutputSet, and associates each with a Process Property; under `bpmn-2.0.2` a completion submits exactly that OutputSet, so every schedule submits all eight, a field hidden for its action as null.

The [Approve schedule](approve.scenario.json) carries a non-negative integer and a duplicate-preserving ordered String list as a direct Product 1 value-domain witness. The [Request changes schedule](request-changes.scenario.json) selects the second conditional route, and the [Abort schedule](abort.scenario.json) selects the default. The scenarios contain no expected answers; their retained CIB evidence (Verify run 43390326342) rolls each completion back at the Simple Boolean condition ([CIB-EXT-0030](../../docs/CIB-BPMN-RELATION-REGISTER.md#cib-ext-0030--a-condition-without-a-declared-language-is-juel)). A separate CIB prefix probe may inspect the candidate group and absence of CIB form data before gateway evaluation.

The source also contains BPMN Documentation and an opaque Rendering extension that Product 2 projects into its definition-bound catalog. Rendering contents never enter semantic execution. The [structured Human Work specification](../../docs/BPM-PLATFORM-STRUCTURED-HUMAN-WORK-SPEC.md) owns the exact value, metadata, routing, Product 2 form, and evidence boundaries.
