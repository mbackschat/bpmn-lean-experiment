# Message key-correlation population scenarios

This directory holds the exact settlement-confirmation source, the answer-free engine-population inputs and one kernel-only single-instance twin (below) selected by the [Message key-correlation specification](../../docs/kernel/semantics/POPULATION-SEMANTICS-SPEC.md). Each Process instance starts and receives one directly addressed non-empty String payload before one definition-scoped correlated publication. The public publication contains no Process instance, Workflow, subscription, locator, selected target, expected outcome, or trace.

- [unique.population-scenario.json](unique.population-scenario.json) initializes two distinct references and publishes one of them.
- [zero.population-scenario.json](zero.population-scenario.json) publishes a third reference absent from both instances.
- [ambiguous.population-scenario.json](ambiguous.population-scenario.json) initializes both instances with the published reference.
- [cross-definition.population-scenario.json](cross-definition.population-scenario.json) initializes equal references under [the primary source](process.bpmn) and [a second definition](process-other-definition.bpmn) that changes only one optional human-readable name while preserving every relevant local id.

These inputs use the closed engine-population schema rather than widening the ordinary single-instance scenario or pipeline-case contracts. Lean, the TypeScript kernel, and Temporal are selected explicitly, while CIB is explicitly `null` under the classified `CIB-LIM-0002` boundary.

[kernel-modeled-key-unbound-standards.scenario.json](kernel-modeled-key-unbound-standards.scenario.json) serves [PC-MESSAGE-08](../../docs/PRACTICAL-CIB7-COVERAGE-TARGET.md#delivery-task-list): a kernel-only single-instance twin on [the unbound-key source](unbound-key.bpmn), the settlement model with its two catches in parallel branches, so the correlated catch waits while `Property_SettlementReference` is still unbound, and a delivery under the key `settlement-42` reaches it before the initializing catch has fired. Its provenance names no CIB revision (`not-applicable`, CIB-LIM-0002), and the differential compares the Lean kernel with the TypeScript kernel on it.

[kernel-unbound-key-publication-standards.population-scenario.json](kernel-unbound-key-publication-standards.population-scenario.json) serves the same row: two instances of [the unbound-key source](unbound-key.bpmn), one of which binds `settlement-42` through its initializing catch, receive a definition-scoped publication of `settlement-42` while the other's key is still unbound, then the same publication again once that key is bound to another reference. It is kernel-only and names no CIB revision for the same reason, and the host refinement test runs it through the hosted population driver.
