# BPMN 2.0.2 sequential Multi-Instance User Task draft profile

This standards profile selects one private executable Process with one sequential Multi-Instance User Task, one once-evaluated ordered `StringList` input, one scalar String completion per generated inner task, index-ordered atomic `StringList` aggregation, and one interrupting `PT1S` Timer Boundary Event whose lifetime is the outer Activity rather than an iteration.

The [profile artifact](profile.json) names BPMN 2.0.2 Clauses 10.3.8 and 13.3.7 plus Tables 10.29 and 10.30 for Multi-Instance Activity execution and runtime counters. Clauses 10.5.5, 10.5.6, 13.3.2, and 13.5.3 plus Tables 10.91, 10.92, 10.101, and 10.122 govern the exact interrupting Timer Boundary Event. Relationships `CIB-AGR-0001` and `CIB-OP-0001` govern only the reused User Task lifecycle and occurrence-identity mapping. This profile selects no CIB Multi-Instance behavior.

Process Start admits only ordered `StringList` values, and User Task completion admits only String values. The selected limits are sixteen input items, 512 canonical UTF-8 bytes per item, and 8,192 canonical UTF-8 bytes for either complete collection. Zero items complete without a controller. A nonempty execution keeps exactly one active inner User Task, preserves the outer Activity and Timer identity through turnover, publishes the output collection only on final completion, and publishes no partial collection after interruption.

The exact account, evidence boundary, and reopen conditions belong to the [Sequential Multi-Instance proposal](../../docs/capsules/SEQUENTIAL-MULTI-INSTANCE-PROPOSAL.md). Status remains `draft`; the profile makes no claim about parallel generation, another Activity type, loop cardinality, completion conditions, expressions, partial output, broader data association, other value types, repeated or nested controllers, another Boundary Event or Timer form, a portable winner for coalesced readiness, general cancellation, compensation, Transactions, CIB Multi-Instance compatibility, production history compatibility, or BPMN Process Execution Conformance.
