# BPMN 2.0.2 Message payload catch mediation draft profile

This standards profile selects one private executable Process whose single Intermediate Catch Message Event is addressed through one Interface Operation and declares one required scalar `DataOutput`. The Event owns one `OutputSet` that requires that output and one direct `DataOutputAssociation` that routes the delivered Message payload into a distinct Process-owned `Property`.

The [profile artifact](profile.json) names BPMN 2.0.2 Clause 8.5.2 for the ItemDefinition, Clause 10.4.1 for Property lifetime, Clause 10.5.1 and Table 10.82 for Catch Event data mediation, and Tables 10.24, 10.25, 10.27, 10.52–10.55, 10.99, 10.101–10.103, and 10.107 for the selected Message, Interface, Event, data-output, OutputSet, and association structure. Relationships `CIB-AGR-0001` and `CIB-OP-0001` govern only the reused User Task lifecycle and occurrence-identity mapping; this profile selects no CIB Message or data-mediation behavior.

The exact source resolves the Message `itemRef` and Event DataOutput `itemSubjectRef` to the same scalar ItemDefinition object. The Event DataOutput, required OutputSet membership, association source, and association target are likewise resolved by parser-object identity, while the distinct Message, DataOutput, association, and Property ids remain explicit through the checked graph and Semantic Process IL.

One occurrence-addressed delivery carries exactly one typed payload value. The accepted transition fills the declared Event DataOutput, routes that value to the association's exact Process Property, consumes the Message wait, and produces the outgoing control token atomically. The payload-free delivery arm remains a separate command and cannot complete this subscription.

The exact account, evidence boundary, and reopen conditions belong to the [Message payload catch mediation capsule](../../docs/capsules/MESSAGE-PAYLOAD-CATCH-MEDIATION-PROPOSAL.md). Status remains `draft`; exact production histories are retained only for the registered bounded schedules, and the profile makes no general claim about history compatibility, multiple Event outputs or OutputSets, optional or while-executing outputs, collections or nested values, assignments, transformations, expressions, data inputs, Activities carrying data, Message name routing, correlation, modeled throws, Message Flows, other Message Event positions, Receive Tasks, Send Tasks, Boundary Events, loops, Multi-Instance, Sub-Processes, Call Activities, vendor extensions, CIB Message compatibility, or BPMN Process Execution Conformance.
