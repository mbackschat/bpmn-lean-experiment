# BPMN 2.0.2 repeatable Event subscriptions draft profile

The [profile artifact](profile.json) selects reusable subscription lifetime across payload-free Message catches, Message-addressed Receive Tasks, exact `PT1S` Timer catches, User Task Message/Timer boundaries, and embedded Sub-Process Timer boundaries. Non-interrupting Messages preserve the same subscription while spawning fresh handler occurrences. A non-interrupting `R/PT1S` Timer boundary replaces each consumed Timer with a fresh occurrence at the next logical deadline. Host completion withdraws future triggers without cancelling already spawned sibling work; regional cancellation follows exact ownership.

Admission permits one executable Process, optionally one depth-one embedded Sub-Process, at most one boundary and one Timer definition, and acyclic fork forests with passive waits. It excludes joins, loops, deeper or multiple child scopes, Message boundaries on Sub-Processes, effects, data mediation, Multi-Instance, Call Activities, Event Sub-Processes and Transactions. The complete Start or resumption burst must fit the unchanged eight-operation closure bound. Recurrence is exactly `R/PT1S`; finite counts, dates, other periods and Timer Start recurrence remain outside this profile.

The host preserves activation-batch order. Within a closed batch it orders User Task completions, Message deliveries, Timer firings and incident commands in that order, using canonical command identity within each class. This is the selected profile policy, not a BPMN-wide precedence rule or physical arrival-time guarantee. Native Timer deadlines survive Workflow continuation; catch-up executes one firing and complete semantic closure at a time. Capacity failures preserve the last committed publication. Existing profiles keep their prior admission and race refusals.

BPMN 2.0.2 owns the semantic account. `CIB-AGR-0001` and `CIB-OP-0001` apply only to reused User Task lifecycle and occurrence identity, as classified in the [relationship register](../../docs/CIB-BPMN-RELATION-REGISTER.md). Scenario provenance references the pristine pinned User Task implementation for those reused premises; no CIB subscription target or race-policy compatibility claim is selected.

The [subscription capsule](../../docs/capsules/REPEATABLE-EVENT-SUBSCRIPTIONS-PROPOSAL.md) owns the precise admission, lifetime, scheduling proof domain, hosting contract and closure status. The [neutral scenarios](../../scenarios/repeatable-event-subscriptions/README.md) bind retained business models to the Lean/core/Temporal pipeline. Profile status remains `draft`; registration does not establish capsule closure, unrestricted BPMN conformance, browser-catalog readiness or a production history-compatibility baseline.
