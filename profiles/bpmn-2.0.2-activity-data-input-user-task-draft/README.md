# BPMN 2.0.2 Activity data-input User Task draft profile

This standards profile selects one private executable Process whose single User Task declares one required scalar `DataInput`, one `InputSet`, one empty `OutputSet`, and one direct `DataInputAssociation` from one Process-owned `Property`. The task becomes active only while that Property is bound, and activation copies the bound value once into the Activity occurrence that owns it.

The [profile artifact](profile.json) names BPMN 2.0.2 Clause 10.4.1 for Property lifetime and accessibility and Clause 10.4.2 for InputSet availability and Data Association execution, together with Tables 10.57, 10.58, 10.59, 10.61, 10.62, and 10.63 for the Activity data interface. Relationships `CIB-AGR-0001` and `CIB-OP-0001` govern only the reused User Task lifecycle and occurrence-identity mapping. This profile selects no CIB Data Association behavior.

Process Start admits exactly the empty payload or one binding named `Property_ReviewContext` whose value is a String or explicit null. A missing binding is unavailable, so the Process stays at the task's incoming control place with no open task, no Activity record, and no Activity-local data. A present binding is available even when its value arm is null, which is what separates the two pre-states. User Task completion admits no submitted value at all, because the selected `OutputSet` is empty; accepted completion disposes the task, its Activity record, and its Activity-local data together and leaves the Process Property unchanged.

The active task publishes exactly its one selected input, named by the exact `DataInput` id. No other Activity-local state enters public observation, and the Process-variable observation continues to expose only Process scope.

The exact account, evidence boundary, and reopen conditions belong to the [Activity data-input mediation proposal](../../docs/capsules/ACTIVITY-DATA-INPUT-MEDIATION-PROPOSAL.md). Status remains `draft`; the profile makes no claim about data outputs, output mediation, further inputs or InputSets, optional or while-executing inputs, Assignments, transformations, expressions, `ItemDefinition`, Data Objects, Data Stores, collection or nested values, mutation while the Activity is active, later reevaluation, another Activity or Task type, Boundary Events, looping, Multi-Instance, Sub-Process scope, Call Activity mappings, forms, authorization, CIB Data Association compatibility, production history compatibility, or BPMN Process Execution Conformance.
