# BPMN 2.0.2 interrupting Sub-Process boundary Timer draft profile

This standards profile selects one embedded Sub-Process carrying one interrupting Timer Boundary Event with an exact `PT1S` duration. The child scope occurrence and its deadline are armed atomically at Sub-Process entry, the child scope's quiescent completion withdraws the deadline and follows the Sub-Process's normal outgoing flow, and a fired deadline terminates the live child region and follows the boundary output instead. The two victories are distinguishable at the public observation boundary, because each route reaches its own follow-on User Task.

The [profile artifact](profile.json) names BPMN 2.0.2 Clause 10.5.5, Clause 10.5.6, Clause 13.3.2, Clause 13.3.4, Clause 13.5.3, Clause 13.5.4, Table 10.92, Table 10.101, and Table 10.122 as normative authority — Clause 13.3.4 for what makes a Sub-Process a legal boundary host and for its quiescent completion rule, Clause 13.5.3 for the boundary handling order, Clause 10.5.6 for what interrupting means, Table 10.92 for the legal `cancelActivity` values per trigger, Clause 10.5.5 with Tables 10.101 and 10.122 for `timeDuration`, Clause 13.3.2 for the nested Activity lifecycle the interruption drives, and Clause 13.5.4 for why an Event Sub-Process is rejected as a host. Relationships `CIB-AGR-0001` and `CIB-OP-0001` govern only the reused User Task interaction boundary — its lifecycle, and the mapping of semantic task identity with stale-command refusal. No CIB Boundary Event, deadline-versus-quiescence race, or retained-evidence claim is selected: the boundary mechanism is vendor-neutral here, and admitting an omitted `cancelActivity` rests on the XSD and CMOF default of `true` rather than on engine behavior.

Two readings are recorded in the [capsule](../../docs/capsules/SUBPROCESS-BOUNDARY-TIMER-SPEC.md) rather than claimed as settled normative text. The arming instant is inherited from the sibling profile, because BPMN 2.0.2 does not fix when a Boundary Event's waiting begins. And Clause 13.3.2's nested-termination prose literally excludes `Ready` and `Active` nested Activities from termination while the same clause's Figure 13.2 gives both states an interruption edge; the capsule resolves that against the figure and Clause 13.5.3's cancellation instruction, so the resolution rests on the standard rather than on engine calibration.

One correctness requirement has no separating witness under this profile and is therefore stated rather than left to a scenario. The deadline must be owned by the *parent* scope occurrence: a child-owned deadline would keep that occurrence permanently non-quiescent, so the normal route would deadlock silently while the deadline route stayed correct.

The exact account, evidence boundary, and exclusions belong to the [interrupting Sub-Process boundary Timer capsule](../../docs/capsules/SUBPROCESS-BOUNDARY-TIMER-SPEC.md). Status remains `draft`; the profile makes no claim about non-interrupting boundaries, nested Sub-Processes or any depth beyond one, more than one child task, other boundary trigger types, more than one boundary per Sub-Process, other host Activity types, other Timer expressions, Transaction or Cancel semantics, Event Sub-Processes, child-local data, a public cancel command, incidents, CIB compatibility, A12 adoption, BPMN Process Execution Conformance, or production history compatibility.
