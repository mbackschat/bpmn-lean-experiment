# CIB Seven 2.2.0 ordinary embedded Sub-Process completion draft profile

This draft profile selects ordinary embedded Sub-Processes nested at most three deep whose every scope is one structured Parallel body of User Tasks, Sub-Processes, Parallel Gateways and None End Events, with quiescent child-scope completion resuming the enclosing body. It also keeps its pre-existing exact multiset class, every one-level topology matching the retained fixture's node and operation multisets, such as the fixture's two-way fork with two child User Tasks ending independently and one enclosing User Task after the scope; the [nested scope-control capsule](../../docs/capsules/NESTED-EMBEDDED-SCOPE-CONTROL-SPEC.md#required-optional-and-excluded-scope) owns the structural class.

The [profile artifact](profile.json) pins CIB Seven `2.2.0` at the reviewed source revision and the same controlled environment as the other `2.2.0` public-service observations. BPMN 2.0.2 supplies the semantic authority. Registered agreement `CIB-AGR-0007` records that the pinned CIB engine exposes the same bounded public lifecycle for the project-authored fixture in both child-completion orders; it does not make CIB's internal scope algorithm authoritative. The nested schedules are standards-only and carry no CIB evidence. The artifact's `features` list still names the one-level fixture, because the cyclic preservation baseline pins the artifact's digest; it does not describe the admitted surface.

Process roots may also hold empty-data Call Activities, repeated, concurrent and nested to depth three, under the [repeated, nested and concurrent Calls capsule](../../docs/capsules/REPEATED-NESTED-CONCURRENT-CALLS-SPEC.md#required-optional-and-excluded-scope). Their `calledElement` is read as an exact in-document key, the key clause of `CIB-EXT-0021`; the artifact's `relationships` list cannot name it for the same pinned-digest reason, so the Call scenarios cite it in their provenance, an owner-accepted substitution that the [contract artifact projections](../../scripts/contract-artifact-projections.test.ts) bind to the register. For the same reason the artifact's `excluded` list still names `call-activities`; this paragraph supersedes it for Process-root Calls. A Start whose hosting instance identity exceeds 256 UTF-8 bytes is refused before Workflow creation.

Every scope that admits a User Task also admits a data-free Service Task bound through a content-bound source overlay, so external effects run concurrently with each other and with human work under the [concurrent scope Service Tasks capsule](../../docs/capsules/CONCURRENT-SCOPE-SERVICE-TASKS-SPEC.md#required-optional-and-excluded-scope). The binding clause of `CIB-EXT-0015` and the concurrent continuation mapping `CIB-OP-0010` govern them; the artifact cannot name either for the same pinned-digest reason, so the Service Task scenarios cite both in their provenance under the same bound substitution. This paragraph supersedes the artifact's `effects`, `external-services` and `vendor-extensions` exclusions for those Service Tasks only; input and output mappings, Error routes, Service Tasks in called bodies or beside a Call, and every other effect or extension stay excluded.

A data-bearing Program, one with a `camunda:inputOutput` declaration on an ordinary Sub-Process or a mapped Service Task, may also hold scope-local data in concurrently live Sub-Process occurrences, merge targets included, under the [concurrent scope data specification](../../docs/capsules/CONCURRENT-SCOPE-DATA-SPEC.md#required-optional-and-excluded-scope). Every read, write, input and output resolves along the performing occurrence's chain under `CIB-EXT-0020`. Service Task input and output mappings follow the mapping clauses of `CIB-EXT-0015`, User Task completion patches follow `CIB-EXT-0005`, and Start bindings follow `CIB-EXT-0006`. Every value is a String of at most 1,024 UTF-8 bytes or a present null. The artifact cannot name these relationships for the same pinned-digest reason, so the concurrent scope data scenarios cite them in their provenance under the same bound substitution, and this paragraph supersedes the artifact's data exclusions for such Programs. Calls in a data-bearing Program, re-entry, structured values and expressions beyond exact `${name}` stay excluded. The profile claims no static capacity envelope for such data: a committed state, publication batch, effect request or History reservation that outgrows its hosted budget ends the Workflow with a typed capacity failure at runtime, after Start, as the proposal's [capacity account](../../docs/capsules/CONCURRENT-SCOPE-DATA-SPEC.md#capacity) states.

The profile reuses `CIB-AGR-0001`, `CIB-AGR-0002`, and `CIB-OP-0001` only for Process lifecycle, active User Task discovery/completion, and generated-host-task mapping to an exact semantic occurrence. The governing boundaries are in the [ordinary embedded Sub-Process completion specification](../../docs/capsules/EMBEDDED-SUBPROCESS-COMPLETION-SPEC.md) and [CIB–BPMN relationship register](../../docs/CIB-BPMN-RELATION-REGISTER.md).

Nesting beyond depth three, unstructured Parallel bodies, Exclusive Gateways and repeated scope activation beyond the [concurrent activation class](../../docs/capsules/CONCURRENT-EMBEDDED-ACTIVATIONS-SPEC.md), Event Sub-Processes, boundary handling, Error propagation, Terminate End Events, child-local data outside data-bearing Programs, Service Tasks outside those capsules, loops, multi-instance, Call Activities inside Sub-Processes or carrying data, transactions, compensation, public scope projection, human-task product features, and every other unlisted BPMN feature remain excluded.

Its status remains `draft`. Results must not be reported as general CIB Sub-Process compatibility or BPMN Process Execution Conformance.
