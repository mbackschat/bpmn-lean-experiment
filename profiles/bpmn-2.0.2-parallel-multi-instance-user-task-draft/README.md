# BPMN 2.0.2 parallel Multi-Instance User Task draft profile

This standards profile selects one private executable Process with one parallel Multi-Instance User Task, one once-evaluated ordered `StringList` input, atomic generation of all bounded inner User Task occurrences, scalar String completion per occurrence, index-ordered atomic `StringList` aggregation, and one interrupting `PT5S` Timer Boundary Event whose lifetime is the outer Activity.

The [profile artifact](profile.json) names BPMN 2.0.2 Clauses 10.3.8 and 13.3.7 plus Tables 10.29 and 10.30 for Multi-Instance Activity execution and runtime counters. Clauses 10.5.5, 10.5.6, 13.3.2, and 13.5.3 plus Tables 10.91, 10.92, 10.101, and 10.122 govern the exact interrupting Timer Boundary Event. Relationships `CIB-AGR-0001` and `CIB-OP-0001` govern only the reused User Task lifecycle and occurrence-identity mapping. This profile selects no CIB Multi-Instance behavior.

Process Start admits one ordered `StringList` and one exact `completionPolicy` String whose value is `all` or `first`; User Task completion admits only String values. The expression language is Simple Boolean v1 and the exact completion condition is `stringEquals(completionPolicy,"first")`. Policy `all` publishes the output collection after every generated inner occurrence completes. Policy `first` terminates every remaining occurrence after the first accepted completion and publishes no output while any planned slot is incomplete. When the planned collection itself has one item, that first completion fills every slot and publishes the complete one-item collection. Neither policy publishes a partial collection.

The selected capacity limits are sixteen input items, 512 canonical UTF-8 bytes per item, and 8,192 canonical UTF-8 bytes for the complete collection. These limits are retained from the maximal natural-completion, Timer-interruption, and early-completion measurements owned by the [parallel Multi-Instance history capacity module](../../packages/temporal-adapter/workflow/src/parallel-multi-instance-history-capacity.ts); seventeen items are refused without state mutation.

The exact account, evidence boundary, and reopen conditions belong to the [parallel Multi-Instance specification](../../docs/capsules/PARALLEL-MULTI-INSTANCE-SPEC.md). Status remains `draft`; the profile makes no claim about sequential generation, another Activity type, loop cardinality, arbitrary data association, partial output, Complex behavior, another completion policy or expression language, another Boundary Event or Timer form, nesting or repetition, a portable winner for coalesced readiness, host-priority semantics, general cancellation, compensation, Transactions, CIB Multi-Instance compatibility, Product 2 parallel Multi-Instance UI, production history compatibility, or BPMN Process Execution Conformance.
