# Definitions module

This module owns M1 definition admission and start orchestration, durable metadata, process-local version ordinals, and exact-source retrieval. The [engine gateway](../../foundation/engine-gateway/README.md) remains the sole compilation and start authority, and the [artifact store](../../foundation/artifact-store/README.md) remains the exact-byte storage mechanism.

`DefinitionDeploymentService.deploy` snapshots every caller-owned input before its first asynchronous boundary. A rejected compilation returns the engine source identity and diagnostics without writing content or metadata. An accepted compilation publishes the exact bytes under the engine-computed SHA-256 before `SqliteDefinitionRepository` allocates and inserts the next positive version for that BPMN process ID inside `BEGIN IMMEDIATE`.

Artifact publication precedes metadata insertion so an artifact conflict cannot create a definition record. A later metadata failure may leave harmless content-addressed orphan bytes. This module deliberately does not delete or prune those bytes and does not deduplicate identical accepted deployments.

The public read boundary lists and retrieves definition metadata and retrieves fresh exact-source bytes. Metadata that points at a missing artifact raises `DefinitionArtifactIntegrityError`; callers never receive an incomplete deployed definition.

Accepted definition metadata includes the gateway-published exact `{ messageStarts, timerStarts }` capability snapshot. A shared SQLite schema epoch runs before every definition, schedule, or publication table owner and refuses older pre-release databases with an actionable reset error instead of inventing capabilities for existing rows or retaining a compatibility reader.

`DefinitionStartService` reads one exact `{processId, version}` row rather than a latest version, snapshots its metadata and artifact bytes, checks the stored byte length, then generates one semantic Process-instance ID and invokes the engine gateway once with the stored source ID, digest, semantic profile, and Process ID as required identities. Missing metadata is a closed not-found outcome; missing or wrong-length source, compiler or identity drift, and any result that is not bound to the selected version are integrity failures. A successful result exposes only the generated semantic instance ID and fresh exact definition metadata. A host-admission rejection exposes that same definition plus a cloned opaque failure.

`DefinitionScheduleService` owns exact-version one-shot Timer Start intent and recovery over a structurally consumed Schedule host. It validates canonical future whole-second activation, recompiles exact stored bytes and capability before first reservation, derives due time from the published duration, persists private identities before host dispatch, and advances only through compare-and-set lifecycle transitions. Cancellation intent commits before pause; a started action wins every race; accepted-but-response-lost creation is recovered by exact create-or-compare; a missing or divergent scheduled host is an integrity failure and is never recreated.

`SqliteDefinitionScheduleRepository` snapshots definition, capability, activation, due time, semantic instance identity, and private host addresses under the public `(processId, version, scheduleId)` key. Process-instance ID, host Schedule ID, and configured Workflow-ID base are independently unique. Terminal host cleanup is durable progress separate from public lifecycle state, and all repository operations finish synchronously so no database transaction spans an asynchronous host call.

`MessageStartPublicationService` owns one exact target and at-most-once dispatch boundary. It revalidates the stored definition, artifact, capability, generated private identities, and host intent; commits `starting` before the only host start call; and uses describe-only recovery afterward. Matching retained evidence promotes to accepted, missing retained evidence becomes indeterminate, unavailable description preserves the prior state, and divergence or private drift becomes a stable integrity tombstone. `SqliteMessageStartPublicationRepository` persists the immutable snapshot and closed compare-and-set graph without holding a transaction across host work.

All three confirmed start paths publish the same exact public Process-instance identity through the module-owned `StartedProcessInstancePublisher` output port. Direct start records after the engine confirms `started`; Schedule and Message publication record only from durable `started` and `accepted` states and retry the same byte-equivalent publication after an index failure. The module does not import or query the `operate` module.

`DefinitionScheduleHttpRoutes` contributes the closed schedule collection and item routes. It validates exact URI identities, query absence, `application/json`, the 1024-byte body ceiling, strict request shape, and canonical whole-second activation before calling the lifecycle service. Public results include only the exact deployed definition, Timer Start capability, semantic Process-instance identity for `started`, and the four public statuses; private host addresses and internal lifecycle states never cross the route.

`DefinitionHttpRoutes` contributes the M1 public Fetch-compatible HTTP boundary without opening a server socket. It validates a closed deployment query and selected XML media types, enforces the configured source-byte ceiling against both `Content-Length` and actual streamed bytes, snapshots stream chunks before producers can mutate them, and invokes admission only after validation. Its exact-version start route accepts `POST` with no query, media type, or body bytes, and maps only public started or rejected results. It publishes only [the public platform contracts](../../contracts/README.md), retrieves exact source bytes with digest-bound identity headers, returns `null` for paths owned by another module, and turns unexpected service or integrity failures into a generic response.

The module does not parse BPMN XML, interpret diagnostics or failures, expose engine-private representations, import any Temporal package, persist or search general Process instances, accept initial variables, provide observation or command operations, provide server composition or UI behavior, or own assurance reports. Server wiring, Temporal SDK calls, Workflow and Worker behavior, recurrence, replacement, latest-version retargeting, Message Start HTTP routing, and fanout remain outside this module. Multipart uploads, CORS, authentication, expected-digest preconditions, pagination, and static serving remain outside this contribution. See [the M1 showcase](../../../showcase/m1-definition-deployment/README.md).
