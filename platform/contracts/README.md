# Platform public contracts

This package owns transport-visible HTTP and event shapes. Contracts carry no service implementation and no BPMN interpretation.

The M1 definition contract publishes exact source identity, located admission diagnostics, deployed definition versions, closed deployment, listing, and definition-version start results, route builders, API error codes, and strict unknown-to-response decoders. A successful start exposes only the semantic Process-instance ID bound to its exact deployed definition version. A pre-start rejection exposes that definition and one opaque failure. Temporal identity, handles, private engine representations, task identity, commands, and mutable nested values do not cross this boundary. The error decoder accepts every published error code, including `methodNotAllowed` and `conflict`, while rejecting private fields and empty messages. Engine diagnostic and start-failure codes remain opaque strings: the platform reports them but does not author their meaning.

The definition-scheduling contract adds the platform-owned Timer Start capability on every exact deployed version; closed one-shot schedule request, item, list, status, and conflict shapes; exact collection and item route builders and matchers; canonical whole-second UTC instant validation; and strict decoders that preserve exact definition and semantic Process-instance identity without admitting Temporal Schedule, Workflow, Run, task-queue, or action fields. All nested definition, capability, schedule, and instance values are immutable at compile time.

The Message Start publication contract widens every definition to exact `{ messageStarts, timerStarts }`, preserves the complete operation-addressed channel, and adds one global exact-target publication item route. Its strict pending, accepted, and indeterminate union exposes a Process-instance identity only for accepted delivery and rejects every private Workflow, Run, Task Queue, Memo, command, program, and engine field.

The current contract deliberately excludes HTTP server behavior, persistence, engine calls, BPMN interpretation, scheduling and publication lifecycle implementation, a definition-start request body, initial variables, instance routes, observation, command submission, pagination, authentication, and UI state. [ARCHITECTURE.md](../../docs/ARCHITECTURE.md#public-contracts) owns the boundary.
